Active Directory Domain Services (AD DS)AbstractActive Directory Domain Services (AD DS) constitute the primary Microsoft Windows Server subsystem for federal identity, credential, and access management (FICAM), authentication, as well as policy enforcement across federal enterprise information systems and server fleets. Its ubiquity has elevated AD from an mere operational dependency to a high-value target for advanced persistent threats and commodity adversaries alike. Over the past decade, offensive techniques have drastically evolved from credential brute-forcing to sophisticated abuse of native AD protocols - most notably Microsoft's Kerberos implementation - to achieve privilege escalation, persistence, and lateral movement. This chapter section systematically decomposes the contemporary AD threat landscape by mapping adversarial actions to the MITRE ATT\&CK framework, quantifying the technical impact of each tactic, and deriving detection logic from underlying protocol artifacts. We first reconstruct the full Kerberos authentication workflow, highlighting protocol-level weaknesses that enable ticket-based and delegation-based attacks. We then instantiate two representative privilege escalation attack chains - Kerberoasting and DCSync - within an isolated Windows Server 2019 domain, capturing all generated Windows Event Log, ETW, and network telemetry. By correlating pre- and post-exploitation event sequences, we extract deterministic indicators of compromise and translate them into Sigma and Kusto Query Language rules suitable for production SIEM deployment. The resulting detection library and experimental dataset are released as a baseline reference for defenders seeking to instrument AD environments with high-fidelity, low-noise, fatigue-deterring alerting.IntroductionActive Directory (AD) is the canonical instantiation of Windows domain services and the single source of truth for federal identity, credential, and access management (FICAM) couple with authentication, and policy, in many federal agencies and institutions. Its six core subsystems - domain services, certificate services, lightweight directory services, federation services, rights management, and integrated DNS - form a tightly-coupled fabric that translates human-readable names to security principals, enforces authorization decisions, and is the harbinger for every interactive and non-interactive logon event. Because every file share, database, mailbox, and management plane ultimately consults AD before granting any access, the directory becomes the nervous system of the enterprise and the bullseye for any adversary who intends to own the domain network.Advanced Persistent Threat (APT) campaigns - defined by the United States Air Force as *"operations conducted by skilled, funded, and mission-driven teams" -* routinely pivot from a single compromised information system to domain dominance by systematically escalating privileges until a Tier 0 account is captured. Once that threshold is crossed, the attacker inherits the ability to rewrite policy, forge tickets, inject persistence, and exfiltrate data at scale. The economic incentive is clear: Kaspersky places the average breach cost at USD 1.41 M for large organizations and USD 108 k for small- to medium-sized businesses, figures that ignore regulatory fines and reputational damage. Consequently, academic and industry research has converged on AD as the highest-leverage chokepoint for both offense and defense.This chapter investigates privilege escalation vectors that abuse native AD semantics rather than unpatched software flaws. We dissect the Kerberos authentication sequence to expose protocol-level weaknesses, map those weaknesses to the MITRE ATT\&CK tactics of credential access and privilege escalation, and instrument a controlled 2019-domain to extract deterministic event-log signatures for two representatitve attacks: Pass-the-Hash (PtH) and Kerberoasting. The resulting telemetry is distilled into detection logic that can be deployed in production SIEM platforms with minimal false-positive rates. By tightly coupling theoretical analysis with reproducible experimentation, we provide defenders a baseline for hunting, alerting, and ultimately disrupting the path from initial foothold to enterprise-wide compromise.BackgroundKerberos is the default authentication protocol in every Active Directory forest and the cryptographic root of trust for every subsequent authorization decision. Understanding its message flow is, therefore, a prerequisite for understanding every modern AD attack, because every offensive primitive - whether it is credential theft, ticket forgery, or delegation abuse - materializes as an intentional deviation from that very flow.Protocol ChoreographyA Kerberos principal (user, service, or machine) begins by turning its password into an AES or RC4 key. This key is used to encrypt a timestamp; the ciphertext is shipped to the *Authentication Server (AS)* that runs inside the *Key Distribution Center (KDC)* on every writable domain controller. Successful decryption proves knowledge of the password and causes AD to mint two objects: (1) a symmetric "logon session key" sealed with the user's key, and (2) a *Ticket Granting Ticket (TGT)* sealed with the long-term key of the `krbtgt` account. Both objects are returned to the client.Whenever the principal needs access to a remote service, for example, it presents its TGT to the *Ticket Granting Service (TGS)*, again part of the same KDC process. The TGS then decrypts the TGT using the `krbtgt` account key, extracts the session key, and - if the TGT is still within its validity window - issues a service ticket encrypted under the target service's long-term key. The client will then forward that service ticket to the application server; the server will, in turn, decrypt it, verify the checksum, and builds a local logon token from the group membership embedded in the ticket. At no point does the KDC maintain per-session state; all authorization data travels inside the tickets themselves.Security Consequences of StatelessnessBecause the KDC is technically stateless, any entity that possesses the `krbtgt` key can fabricate TGTs that the TGS will accept as authentic because it if it was approved and issued by the KDC itself, it has to be genuine. It knows no other way. It's job is if it receives a ticket - validate it and return. This is because AD and when Kerberos was integrated, have all been built on a model of inherent trust. Everything trusts everything in vanilla Active Directory (e.g., no hardening, straight AD out-of-the-box). This is also because the attack surface was nothing like it is today almost 20 years ago, and at that time, that security model of placing inherent trusts in users, domain objects, devices was the best security was at that time. Sure, now it seems weak, but that's just how evolution goes. So, the TGS will accept the forged, or fraudulent ticket because that's its job.Understand that there is one account that is highly protected, that most domain admins don't even have access to it: the krbtgt account. The krbtgt account's password is therefore the most sensitive secret in the forest; yet, by default, it is chaned only when the domain functional level is raised, during a breach, or a manual reset. Which by the way, the password has to be rotated twice in a row because and if notA stolen krbtgt key grants an attacker perpetual ticket-forging capability until every domain controller is forced to rotate the key twice - an operation that is rarely performed and, if done correctly (as most fail to do it right the first time around), can break existing trusts, and bring your AD architecture to a screaming halt with just a click of one mouse button (or Enter key). Statelessness also means that every field inside a TGT is trusted once the outer wrapper is decrypted, giving attackers a convenient vehicle for injecting false group memberships arbitrary expiration times, or delegation flags that survive for the life of the ticket.Active Directory Attack Lifecycle(foothold → enumeration → escalation → persistence → objective)The following narrative mirrors the trajectory shown in Figure 2: an intruder who already controls a low-privileged beacon on an arbitrary information system and wants to become an omnipotent tenant of the forest.
