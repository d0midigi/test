# 2.6.4 Prevention Still Matters

Assume breach should not be interpreted as abandonment of prevention.

Preventative controls remain essential because every attack path interrupted early reduces adversary opportunity. Strong authentication, patching, protocol hardening, endpoint protection, network segmentation, secure configuration, privileged-access controls, certificate governance, and vulnerability management all reduce the probability or impact of compromise.

The difference is that no single preventative layer is allowed to carry the entire security model.

A phishing-resistant authenticator can substantially reduce credential phishing, but it does not correct excessive directory permissions.

Endpoint detection can identify malicious activity, but it does not remove dangerous trust relationships.

Network segmentation can constrain reachability, but it does not correct a certificate template that grants unintended authentication authority.

A Security Technical Implementation Guide (STIG) can improve configuration consistency, but compliance with individual settings does not prove that no indirect control path exists.

Assume breach therefore complements prevention rather than replacing it.

Prevention reduces opportunities.

Containment limits what follows when prevention fails.

Detection identifies when trust is being abused.

Recovery restores authoritative state when trust can no longer be relied upon.

The strength of the identity architecture lies in the interaction of all four.
