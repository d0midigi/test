# 2.6.2 Privileged Administration Changes Under Assume Breach

Administrative design provides one of the clearest examples of assume-breach reasoning.

Consider an administrator who uses the same privileged account to administer Domain Controllers, member servers, and ordinary workstations. From an operational perspective, the arrangement is simple. One account can perform all necessary tasks.

From an assume-breach perspective, the arrangement creates a dependency in the opposite direction.

If any lower-trust system on which that credential is exposed becomes compromised, the adversary may obtain material capable of reaching higher-trust systems.

The architecture has allowed the security of Tier 0 administration to depend on the security of systems outside Tier 0.

That dependency is backwards.

Administrative tiering, Privileged Access Workstations (PAWs), Secure Administrative Workstations (SAWs), authentication restrictions, credential isolation, and related privileged-access controls are attempts to correct that condition. They do not exist merely to inconvenience administrators or create more accounts. They are mechanisms for preventing compromise in one administrative plane from automatically propagating into a more sensitive one.

This is a deeper principle than account separation.

It is control-plane separation.

The privileged identity, the workstation from which it is used, the systems to which it may authenticate, the credentials it exposes, and the infrastructure capable of managing those systems all contribute to the administrative boundary.

If a Tier 0 administrator uses a hardened workstation but that workstation can be remotely controlled by a lower-tier management platform, the administrative boundary remains incomplete.

If Domain Controllers are isolated but their hypervisor can be administered from ordinary IT infrastructure, the virtualization plane may become an indirect path around the isolation.

If privileged credentials are carefully protected but the backup platform can restore arbitrary Domain Controller state, backup administration enters the same trust discussion.

Assume breach forces those indirect dependencies into view.
