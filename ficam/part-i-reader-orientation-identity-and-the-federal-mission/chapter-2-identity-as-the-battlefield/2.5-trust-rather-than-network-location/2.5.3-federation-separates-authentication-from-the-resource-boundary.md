# 2.5.3 Federation Separates Authentication From the Resource Boundary

Federation extends this concept beyond traditional Active Directory trusts.

In a federated model, an application may not authenticate the user directly at all. Instead, it accepts an assertion produced by an identity provider.

The relying application trusts the issuer, the signing mechanism, and the claims carried within the token under the configured federation relationship.

This changes where security authority resides.

Compromise of the application remains important.

Compromise of the identity provider may be more consequential because the identity provider can potentially influence the assertions consumed by multiple applications.

Compromise of signing material can be more consequential still because cryptographic trust may allow an attacker to manufacture assertions that appear to originate from the legitimate identity authority.

The network location of the attacker does little to answer whether such a token will be accepted.

The relying party evaluates the trusted assertion.

This is identity-centric trust in its clearest form.
