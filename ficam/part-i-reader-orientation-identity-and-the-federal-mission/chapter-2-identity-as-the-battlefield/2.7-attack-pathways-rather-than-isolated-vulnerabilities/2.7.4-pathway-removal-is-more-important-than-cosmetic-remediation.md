# 2.7.4 Path Removal Is More Important Than Cosmetic Remediation

Attack-path remediation should be evaluated by whether the path has actually been broken.

Suppose a user has indirect control over a privileged group through three intermediate relationships. Removing one relationship may close the known route.

If another equivalent route remains, the underlying exposure has not been eliminated.

Similarly, resetting a compromised service-account password may remove one credential but leave the account's excessive privilege untouched. Hardening a certificate template may close one escalation path while another template grants equivalent authentication authority. Removing a user from Domain Admins may reduce visible privilege while delegated rights still permit the same user to regain that membership.

This is why validation matters.

Remediation should not end with confirmation that a configuration was changed. The original attack condition should be tested again from the adversary's perspective.

Can the principal still reach the target?

Can equivalent authority be obtained through another edge?

Did the remediation unintentionally create a new dependency?

Did the control survive replication, policy processing, or synchronization?

The goal is not merely to change the configuration.

It is to change the reachable security state.
