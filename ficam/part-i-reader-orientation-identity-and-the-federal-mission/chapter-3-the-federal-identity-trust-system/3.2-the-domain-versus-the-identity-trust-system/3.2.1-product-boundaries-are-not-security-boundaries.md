# 3.2.1 Product Boundaries Are Not Security Boundaries

Technology teams naturally divide environments by product.

The Active Directory team manages Domain Controllers.

The PKI team manages Certification Authorities.

The cloud team manages Microsoft Entra ID.

The network team manages Remote Authentication Dial-In User Service (RADIUS), Network Policy Server (NPS), Virtual Private Network gateways, and related network-access controls.

Application teams manage relying services.

Another group may own identity governance or privileged-access tooling.

These boundaries are useful for assigning responsibility.

They are unreliable as security boundaries.

A certificate issued by the PKI team may authenticate to a system administered by the Active Directory team.

A synchronization account managed by the identity team may possess rights in both Active Directory and Microsoft Entra ID.

A virtualization administrator outside the directory team may control the hypervisor beneath a Domain Controller.

A network administrator may control authentication infrastructure governing administrative access to devices relied upon by identity services.

From the adversary's perspective, the team responsible for the system is irrelevant.

Authority is what matters.

If compromise of System A provides a path to control System B, the two systems participate in the same security problem regardless of which teams own them.
