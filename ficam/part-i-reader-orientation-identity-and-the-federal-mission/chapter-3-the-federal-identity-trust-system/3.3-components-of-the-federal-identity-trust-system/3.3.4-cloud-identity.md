# 3.3.4 Cloud Identity

Cloud identity introduces another authoritative plane.

Microsoft Entra ID and comparable identity platforms maintain users, groups, devices, applications, service principals, administrative roles, authentication methods, tokens, Conditional Access state, and numerous relationships that do not exist solely in on-premises Active Directory.

Hybrid environments frequently connect those planes rather than replacing one with the other.

A user may originate on premises, synchronize to the cloud, receive cloud-specific role assignments, authenticate through modern authentication, and access applications that never communicate directly with a Domain Controller.

At the same time, the user's on-premises identity may remain authoritative for other resources.

Security analysis therefore has to preserve the distinction between the two identity systems while also examining the pathways connecting them.

Treating Microsoft Entra ID as simply “Active Directory in the cloud” obscures meaningful differences in authentication, authorization, object types, token behavior, administrative roles, applications, and trust relationships.

Treating the systems as completely independent is equally inaccurate when synchronization and hybrid authentication join them.
