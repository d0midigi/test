# 3.3.3 Federation Services

Federation allows one identity authority to make assertions that another system accepts.

The relying system does not necessarily validate the user's original credential. Instead, it trusts the identity provider's statement about the authenticated principal and associated claims.

This is an efficient way to extend access across application and organizational boundaries.

It also transfers trust.

The relying party now depends upon the identity provider's authentication process, signing infrastructure, claims configuration, and governance.

If those components are compromised or misconfigured, downstream applications may accept identity information that is cryptographically valid yet operationally false.

Federation therefore belongs inside the identity security boundary even when the relying application and identity provider are administered separately.
