# 3.4.2 Formal Authorization Changes the Meaning of Evidence

Federal systems generally operate within formal risk-management and authorization structures. That makes security evidence important in a way that extends beyond troubleshooting or operational monitoring.

A configuration is not merely something the administrator believes to be secure. Its security state may need to be demonstrated.

An access-control design may require evidence showing how privileged authority is assigned. An authentication requirement may require configuration evidence, implementation documentation, assessment results, and continuing monitoring. A remediation may need to show not only that a setting changed but that the original risk has been addressed and the associated finding can legitimately be closed.

This requirement has direct implications for identity security.

Consider an excessive directory permission discovered during an assessment. Removing the Access Control Entry is only the technical change. A mature remediation process should also establish why the permission existed, whether equivalent permissions exist elsewhere, whether any dependent process relied on it, whether exploitation occurred, whether the corrected state persists after replication and administrative changes, and what evidence demonstrates that the original control weakness has been removed.

The difference between configuration and demonstrated control effectiveness becomes important here.

An environment may contain the right setting today because an administrator changed it yesterday.

A defensible security posture requires greater confidence that the setting represents governed state rather than temporary good fortune.
