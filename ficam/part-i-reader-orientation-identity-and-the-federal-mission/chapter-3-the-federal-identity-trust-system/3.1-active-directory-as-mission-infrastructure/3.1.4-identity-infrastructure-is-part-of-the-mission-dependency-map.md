# 3.1.4 Identity Infrastructure Is Part of the Mission Dependency Map

System dependency mapping traditionally focuses on infrastructure such as networks, power, virtualization, storage, databases, and external services.

Identity belongs on that map.

The dependency is sometimes direct. An application authenticates users against Active Directory.

Sometimes it is indirect. The application uses a local account, but the administrators who maintain the server authenticate through the domain.

Sometimes the dependency exists only during recovery. A backup platform relies on domain authentication for administrators, or restoration procedures depend on privileged identities stored in another system.

These indirect relationships matter because failure analysis performed only during normal operation may overlook the identity systems needed during an emergency.

A recovery plan that requires access to Active Directory but is intended to recover Active Directory has an obvious circular dependency.

A backup system whose administrators require the same compromised directory to authenticate may become difficult to trust during forest recovery.

A privileged-access vault that depends upon infrastructure inside the compromised administrative boundary may not provide the clean recovery path its design intended.

Mission dependency analysis must therefore include not only what identity services support normal operations, but what identity services are required to restore those operations when trust has failed.

That concern becomes central later when the book reaches Tier 0 recovery and trust restoration.
