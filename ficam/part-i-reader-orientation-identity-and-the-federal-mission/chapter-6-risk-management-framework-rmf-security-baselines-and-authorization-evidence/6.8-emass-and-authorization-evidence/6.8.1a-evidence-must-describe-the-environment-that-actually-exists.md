# 6.8.1a Evidence Must Describe the Environment That Actually Exists

One of the most damaging habits in authorization work is documenting the environment the command intends to operate rather than the one currently operating.

Identity systems are particularly vulnerable to this problem because meaningful security changes can occur without major architecture changes.

A new server may require a diagram update.

Adding a principal to a privileged group does not.

Neither does changing an Access Control Entry on an Organizational Unit.

A certificate template can acquire new enrollment permissions without changing the PKI diagram.

A service account can gain replication rights without altering the network topology.

A Group Policy Object can be relinked in seconds.

A federation claim can be modified without deploying another identity provider.

From the perspective of the network drawing, almost nothing happened.

From the perspective of authority, a great deal may have changed.

The eMASS package therefore has to remain connected to the operational state of the identity system. Architecture diagrams, implementation statements, configuration exports, assessment evidence, vulnerability results, and risk entries should describe compatible versions of the environment.

When those artifacts drift apart, reviewers may unknowingly evaluate a security state that no longer exists.

Consider a system security plan stating that privileged administrators use dedicated administrative workstations exclusively for Tier 0 operations. The control was assessed successfully eighteen months earlier. Since then, an emergency remote-management platform has been introduced and given administrative reach to Domain Controllers.

The original statement may still be factually correct in one narrow sense: the administrators themselves continue using their approved workstations.

The security architecture, however, now contains another administrative path.

If the management platform is not represented in the authorization evidence, the package no longer describes the effective Tier 0 boundary.

That is configuration drift at the authorization level.
