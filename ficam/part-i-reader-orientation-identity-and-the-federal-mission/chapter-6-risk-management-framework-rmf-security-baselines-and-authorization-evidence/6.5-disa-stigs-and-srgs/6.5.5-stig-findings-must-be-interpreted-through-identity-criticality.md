# 6.5.5 STIG Findings Must Be Interpreted Through Identity Criticality

A STIG finding describes a deviation from an expected security requirement.

It does not by itself describe the complete consequence of exploiting that deviation.

Identity architecture supplies that context.

Consider the same weakness on two servers.

The first server provides an ordinary internal application.

The second manages certificates, identity synchronization, endpoint administration, or Domain Controller virtualization.

The technical finding may be identical.

The second system occupies a substantially more important position in the identity trust system.

That difference should affect prioritization.

The same principle applies within Active Directory.

A security weakness affecting an ordinary workstation does not necessarily have the same consequence as the same weakness on a Privileged Access Workstation.

A member server that never receives privileged authentication has a different security role from one on which Domain Admin sessions regularly occur.

A system controlled by Tier 0 administrators belongs in a different risk discussion from one isolated from the administrative control plane.

STIG severity and mission consequence are therefore related but distinct.

The STIG gives the organization a consistent technical finding.

Attack-path and mission analysis determine what that finding means in the actual environment.
