# 6.5.4 Identity Baselines Must Include Relationships

Group Policy is particularly important to STIG implementation in Windows environments because it allows many security settings to be centrally defined and enforced.

This creates substantial operational advantages.

Settings can be standardized.

Changes can be versioned and tested.

Domain Controllers can receive common policy.

Member servers can receive role-specific configuration.

Workstations can be separated from administrative systems.

Configuration can be reapplied automatically when local state diverges.

DISA's published GPO packages are intended to assist that implementation process, but DISA explicitly directs administrators to test the supplied policies before production use.

The distinction between baseline and GPO should remain clear.

The STIG defines the security requirement.

The GPO is one mechanism for implementing some portion of it.

This matters because simply importing a supplied GPO does not establish that the requirement is effective.

Policy precedence can alter the resulting setting.

Another GPO can override it.

A security filter may prevent application.

A Windows Management Instrumentation filter can change scope.

An Organizational Unit can be linked incorrectly.

Loopback processing can affect resulting policy.

A system can fail to process Group Policy.

A local configuration can survive when the intended domain policy never reaches the target.

Assessment must therefore examine Resultant Set of Policy and effective configuration rather than assuming that existence of the baseline GPO proves implementation.

For Active Directory security, another issue is even more important:

Who can modify the baseline GPO?

A hardened Domain Controller configuration loses much of its value if a lower-trust principal can alter the policy responsible for enforcing it.

The security boundary includes the policy object, its permissions, its associated SYSVOL content, and the administrative systems from which the policy is managed.

The baseline itself becomes a privileged object.
