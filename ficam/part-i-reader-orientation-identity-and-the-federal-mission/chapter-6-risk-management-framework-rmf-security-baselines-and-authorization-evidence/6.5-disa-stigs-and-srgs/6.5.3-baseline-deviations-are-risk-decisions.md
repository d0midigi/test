# 6.5.3 Baseline Deviations Are Risk Decisions

Active Directory creates a special baseline problem because the directory service and the operating system hosting it are inseparable operationally but distinct analytically.

A Domain Controller is a Windows Server system.

It is also an authentication authority, directory replica, Kerberos Key Distribution Center, policy participant, replication partner, and repository of security principals and authorization data.

Hardening only the Windows Server operating system therefore addresses only part of the security state.

The surrounding directory architecture also matters.

Group Policy affects security configuration.

Domain and forest configuration affect trust.

Directory permissions affect administrative authority.

Authentication policy affects how credentials can be exercised.

Audit policy affects visibility.

Organizational Unit structure affects delegation and policy application.

Replication privileges affect access to sensitive directory state.

The effective Domain Controller security posture is produced by the interaction of these elements rather than by one local security template.

This distinction becomes especially important because many settings applied to Domain Controllers are centrally managed through Group Policy rather than configured individually on the server.

DISA provides STIG-related Group Policy Object packages specifically to assist administrators with implementing applicable STIG settings. DISA cautions that these GPOs must be tested before production deployment and notes that the packages contain most applicable GPO-based settings rather than representing a universal one-click implementation of every requirement.

That warning is operationally significant.

A baseline package is not an architecture-aware deployment engine.

It does not know whether a mission application depends on the protocol being disabled.

It does not know whether a downstream service will fail under a stricter authentication policy.

It does not understand replication topology, legacy application dependencies, mission-partner requirements, or specialized administrative workflows.

The administrator has to supply that understanding.
