# 6.6.6 Baseline Versioning Matters

A security baseline is not static.

Operating systems change.

Security features are introduced.

Defaults change.

Protocols are deprecated.

Adversary techniques evolve.

Product behavior changes through cumulative updates and new releases.

Microsoft continues revising its Windows Server security baselines; for example, it published a February 2026 revision of the Windows Server 2025 security baseline after the original Windows Server 2025 baseline release.

That means an organization should know which baseline version it implemented.

“Microsoft baseline applied” is not sufficient configuration-management information.

Which baseline?

For which operating-system release?

Which revision?

What deviations were approved?

Which settings were later changed locally?

What new recommendations appeared in the next baseline?

Without version control, the organization cannot distinguish deliberate tailoring from historical drift.

This becomes especially important during operating-system upgrades.

A security configuration appropriate to Windows Server 2022 should not simply be assumed to represent the complete Windows Server 2025 security model. Microsoft continues to publish product-specific baselines precisely because supported features and recommended configurations evolve.

The same principle applies to STIG versions.

Baseline currency is part of configuration state.
