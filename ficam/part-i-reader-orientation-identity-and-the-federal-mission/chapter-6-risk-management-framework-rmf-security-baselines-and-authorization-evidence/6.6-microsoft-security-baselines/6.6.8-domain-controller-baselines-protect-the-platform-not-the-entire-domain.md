# 6.6.8 Domain Controller Baselines Protect the Platform, Not the Entire Domain

This distinction deserves explicit treatment because it is fundamental to the security model used throughout Contested Terrain.

A Domain Controller baseline protects the Domain Controller platform.

It does not define the complete security state of the domain.

The baseline can harden authentication protocols.

It can improve audit policy.

It can restrict insecure services.

It can configure cryptographic behavior.

It can constrain remote access.

It can establish appropriate operating-system security settings.

Those protections materially reduce attack surface.

But consider an environment in which every Domain Controller perfectly conforms to both the applicable DISA requirements and Microsoft-recommended baseline.

A low-privileged user has GenericAll over an administrative group.

Another group can modify a Group Policy Object linked to the Domain Controllers Organizational Unit.

A service account has unnecessary replication rights.

A Certification Authority permits issuance of authentication certificates through an unsafe configuration.

Tier 0 administrators routinely log on to Tier 1 servers.

A virtualization-management platform controlling the Domain Controllers is administered from ordinary enterprise workstations.

The Domain Controllers themselves can remain impeccably hardened.

The domain is still exposed.

The reason is structural.

Platform hardening reduces weaknesses in the systems implementing identity authority.

Attack-path engineering constrains who can reach and manipulate that authority.

Neither replaces the other.
