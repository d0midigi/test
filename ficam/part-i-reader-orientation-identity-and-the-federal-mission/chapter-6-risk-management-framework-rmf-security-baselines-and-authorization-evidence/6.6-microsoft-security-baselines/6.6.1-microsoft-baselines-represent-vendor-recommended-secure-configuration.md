# 6.6.1 Microsoft Baselines Represent Vendor-Recommended Secure Configuration

Microsoft's baseline philosophy is deliberately different from configuring every available security option to its most restrictive value.

A useful baseline has to be secure enough to materially reduce attack surface while remaining deployable across enterprise environments.

That means baseline engineering includes compatibility judgment.

Some Windows security settings can be made more restrictive than Microsoft's recommendation.

That does not automatically mean they should be.

The stricter setting may break functionality, produce unsupported behavior, or create operational complexity disproportionate to the security benefit.

This is an important principle for DoD administrators because hardening discussions can otherwise become an informal competition over which configuration is most restrictive.

Restriction is not the objective.

Risk reduction is.

A setting that prevents a mission system from functioning may create an availability risk greater than the threat it was intended to mitigate.

A setting that is left permissive solely because changing it would be inconvenient creates the opposite problem.

Baseline engineering exists between those extremes.
