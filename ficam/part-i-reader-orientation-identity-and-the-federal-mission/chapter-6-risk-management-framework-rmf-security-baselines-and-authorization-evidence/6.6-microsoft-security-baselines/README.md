# 6.6 Microsoft Security Baselines

Microsoft Security Baselines occupy a different position from DISA STIGs and SRGs.

They are vendor-developed recommended security configurations for Microsoft products rather than DoD-mandated hardening guidance. Microsoft describes its Security Compliance Toolkit (SCT) as a collection of tools that allows enterprise administrators to download, analyze, test, edit, and store Microsoft-recommended security configuration baselines.

That difference in authority should remain explicit.

In a DoD system, the Microsoft baseline does not supersede the applicable DISA STIG.

Nor should it be dismissed merely because the DISA baseline is authoritative for the DoD environment.

The two serve related but different engineering purposes.

DISA expresses DoD security requirements for the technology.

Microsoft possesses detailed knowledge of the behavior, supported configuration, security features, compatibility implications, and intended defensive posture of the product it develops.

For Active Directory engineering, both perspectives are useful.

The correct question is not which baseline “wins” in the abstract.

The correct question is what the applicable DoD requirement demands, what Microsoft recommends for the product, where those positions overlap or differ, and what configuration the mission environment can implement without creating unacceptable risk.
