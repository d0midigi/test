# 6.6.5 Microsoft Baselines and DISA STIGs Should Be Compared, Not Blended Blindly

In a DoD Active Directory environment, there is a temptation to merge Microsoft and DISA settings into one “maximum security” Group Policy and deploy the union.

That is not sound baseline engineering.

The two baselines may contain different settings, different values, different assumptions, and different release cadences.

Where the applicable STIG establishes a DoD requirement, that requirement governs within its applicability.

Microsoft guidance remains valuable for understanding product behavior, newly introduced controls, security features not yet represented in an existing STIG release, and the vendor's recommended configuration.

The difference itself can be useful engineering evidence.

If Microsoft introduces a new defensive setting in Windows Server 2025 and the currently applicable DoD baseline does not yet address it, the absence of a STIG rule does not mean the feature lacks security value.

Conversely, if Microsoft leaves a setting less restrictive for broad compatibility while the DoD STIG requires a stronger configuration, the DoD environment cannot simply adopt the vendor default and declare the requirement satisfied.

The baselines answer different institutional questions.

DISA asks what configuration DoD requires for the technology within its governance framework.

Microsoft asks what secure configuration it recommends for the product while accounting for product behavior and enterprise supportability.

A mature engineering process preserves both sources rather than flattening them into one anonymous spreadsheet of settings.
