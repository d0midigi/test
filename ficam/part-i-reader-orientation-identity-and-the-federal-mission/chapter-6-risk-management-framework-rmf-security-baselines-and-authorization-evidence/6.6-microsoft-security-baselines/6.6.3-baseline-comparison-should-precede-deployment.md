# 6.6.3 Baseline Comparison Should Precede Deployment

Security baselines should not be imported directly into production merely because Microsoft published them.

Microsoft's own baseline release guidance instructs organizations to test recommended configurations and customize or implement them as appropriate for the environment.

That testing requirement becomes especially important for Domain Controllers.

Domain Controllers support authentication, directory access, replication, policy processing, service discovery, certificate-based authentication dependencies, trust relationships, and applications that may have existed for years.

A setting that appears harmless in an isolated Windows Server test may affect:

Kerberos behavior.

NTLM fallback.

LDAP clients.

SMB communication.

Remote administration.

Certificate authentication.

Domain joins.

Trust operations.

Directory replication.

Legacy applications.

Administrative tooling.

The safe implementation pattern is therefore controlled comparison, laboratory validation, limited deployment, observation, and progressive enforcement.

The baseline provides the target.

Testing determines what must happen before the environment can reach it safely.
