# 6.6.7 Baseline Drift Is an Identity-Security Problem

Configuration drift occurs when the operational state moves away from the approved baseline.

Some drift is obvious.

A security setting is changed.

A policy is disabled.

An administrator creates a local exception.

Other drift is architectural.

A new application requires an older protocol.

A management agent creates another administrative path.

A certificate service introduces a new authentication mechanism.

A server changes role without receiving the corresponding baseline.

A new Group Policy Object begins overriding the original configuration.

This distinction matters because technically identical settings can have different security meaning as the surrounding architecture changes.

An NTLM configuration may have been accepted originally because only one isolated legacy system required it.

Three years later, the same configuration remains while the network has expanded and new systems accept NTLM.

The baseline value did not change.

The exposure did.

Baseline monitoring therefore should not be limited to comparing registry values.

The organization must also revisit assumptions underlying approved deviations.

Microsoft's current Windows Server 2025 OSConfig baseline functionality explicitly includes the ability to maintain configuration and detect or control drift, reinforcing the importance of baseline state as an ongoing lifecycle concern rather than a one-time deployment event.
