# 5.11.5 Machine Identity Is More Than a Computer Object

Active Directory computer accounts provide a familiar example of non-person identity.

A domain-joined computer possesses a directory object, a Security Identifier, credential material, group relationships, attributes, and an authentication relationship with the domain.

It is a security principal.

That fact is easy to overlook because administrators often think of computer objects as inventory representations of physical or virtual machines.

They are more than inventory.

Machine identities participate in Kerberos, secure-channel relationships, access control, Group Policy, delegation, certificate enrollment, and other security processes.

A computer account can therefore become an offensive asset.

Control over a machine identity may provide useful authentication material, Service Principal Name manipulation opportunities, delegation pathways, or access based on permissions assigned to computers rather than users.

Modern device identity broadens the concept further. A device may possess an Active Directory computer identity, a Microsoft Entra device identity, certificates, Trusted Platform Module (TPM)-protected keys, management state, and compliance attributes simultaneously.

The physical device has become represented through several trust systems.

Securing machine identity requires understanding which representation each relying service is actually trusting.
