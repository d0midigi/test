# 5.2.1 Enterprise ICAM Does Not Eliminate Local Identity Engineering

Centralized enterprise identity services provide obvious benefits.

Identity attributes can be made more consistent.

Duplicate credentials can be reduced.

Deactivation can propagate more effectively.

Common standards improve interoperability.

Mission partners can be supported through defined interfaces rather than one-off local solutions.

The DoD reference design identifies these kinds of consistency, scalability, user-experience, and cybersecurity benefits as reasons to consume enterprise ICAM capabilities where appropriate.

But consuming enterprise identity does not eliminate local security responsibility.

A mission application still determines what access it grants.

A local Active Directory environment still controls delegated permissions.

A Component still governs its own administrative paths.

A relying system must still protect the mechanisms through which enterprise identity becomes local authorization.

The enterprise service can provide an accurate identity and still be used badly.

A perfectly maintained enterprise attribute can still be mapped into an overprivileged application role.

A valid authentication assertion can still be accepted by an application that grants too much authority.

An accurately deprovisioned enterprise identity may still have a forgotten local account that is not governed by the same lifecycle.

The security of enterprise ICAM therefore depends partly on the consuming system.

Identity centralization improves the source of truth.

It does not automatically correct every downstream trust decision.
