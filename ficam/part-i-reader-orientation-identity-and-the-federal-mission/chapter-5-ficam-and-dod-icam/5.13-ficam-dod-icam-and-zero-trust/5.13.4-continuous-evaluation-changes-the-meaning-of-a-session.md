# 5.13.4 Continuous Evaluation Changes the Meaning of a Session

Traditional authentication models often place most trust evaluation at session establishment.

The user authenticates.

The application grants a session.

The session remains accepted until logout, expiration, or another terminating event.

Zero Trust pushes the architecture toward reevaluating access as conditions change.

That can include changes to identity risk, device state, privilege, application context, session behavior, or another relevant signal.

The conceptual change is important.

Authentication no longer needs to be treated as a permanent declaration that the principal is trusted for the remainder of the session.

It becomes evidence contributing to a continuing authorization state.

This is particularly valuable when an identity changes after authentication.

A user's account is disabled.

A privileged role is revoked.

A device becomes noncompliant.

A risk condition appears.

A credential is reported compromised.

The more quickly those changes affect active access, the smaller the window in which stale trust remains usable.

The implementation details differ across technologies, but the architectural objective is consistent: authorization should respond to meaningful changes in trust rather than waiting indefinitely for the next full login.
