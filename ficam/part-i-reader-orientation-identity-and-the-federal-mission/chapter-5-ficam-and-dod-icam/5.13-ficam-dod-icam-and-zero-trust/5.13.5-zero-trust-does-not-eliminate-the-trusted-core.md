# 5.13.5 Zero Trust Does Not Eliminate the Trusted Core

The phrase _never trust, always verify_ can create the impression that Zero Trust eliminates trusted infrastructure.

It does not.

Verification itself requires authorities.

Someone must determine which identity is valid.

Someone must issue or bind the credential.

Someone must maintain authoritative attributes.

Someone must establish device state.

Someone must sign federation assertions.

Someone must administer the policy engine.

Someone must determine which administrators can modify all of those systems.

These functions form a trusted control plane even in a Zero Trust architecture.

The objective is not absence of trust.

It is explicit, constrained, continually evaluated trust supported by protected authorities.

This makes the trusted core more important, not less.

If an adversary controls the system that tells the policy engine which users are administrators, continuous evaluation simply processes adversary-controlled state continuously.

If an adversary controls the certificate authority used to establish device identity, strong device-based policy may accept adversary-manufactured credentials.

If an adversary controls the management platform supplying compliance state, the policy engine can be misled about endpoint trust.

Zero Trust does not remove Tier 0.

It expands the need to identify which systems possess Tier 0-equivalent influence over access decisions.
