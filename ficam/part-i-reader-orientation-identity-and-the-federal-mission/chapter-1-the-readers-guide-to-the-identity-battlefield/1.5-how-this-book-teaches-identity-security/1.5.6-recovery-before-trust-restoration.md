# 1.5.6 Recovery Before Trust Restoration

The sixth rule is that operational recovery does not automatically restore identity trust.

This distinction becomes critical after major compromise.

A server can be online and still be untrustworthy.

A user can have a new password while an attacker retains another authentication mechanism.

A Domain Controller can be rebuilt while another compromised Domain Controller replicates malicious state back into the environment.

An endpoint can be reimaged while forged Kerberos tickets remain valid.

A Certification Authority can continue issuing certificates while an attacker retains a copy of the CA private key.

AD FS can resume service while a stolen token-signing key remains usable.

Microsoft Entra ID can remain available while malicious application credentials, refresh tokens, service principals, or cross-tenant trust relationships persist.

Identity recovery must therefore answer a deeper question:

Which trust anchors were compromised?

Trust anchors include more than passwords.

They may include:

* the KRBTGT account;
* Domain Controllers;
* privileged administrative credentials;
* certificate-authority private keys;
* certificate templates;
* federation signing keys;
* synchronization accounts;
* application secrets;
* cloud service principals;
* privileged access systems;
* backup infrastructure; or
* management platforms capable of controlling Tier 0 systems.

When those components are compromised, restoration requires more than removing malware.

Keys may need to be rotated.

Certificates may need to be revoked and reissued.

Domain Controllers may need to be rebuilt.

Administrative workstations may need to be reestablished from trusted sources.

Replication must be validated.

Federation partners may need to reestablish trust.

Cloud sessions may need to be revoked.

Service-principal credentials may need replacement.

Only after those authoritative mechanisms are revalidated can the environment credibly claim that trust has been restored.

This distinction between availability recovery and trust recovery becomes one of the defining principles of the later recovery chapters.
