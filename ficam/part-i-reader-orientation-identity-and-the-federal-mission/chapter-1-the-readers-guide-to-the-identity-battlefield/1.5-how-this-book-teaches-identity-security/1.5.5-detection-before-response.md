# 1.5.5 Detection Before Response

The fifth rule is that response begins with reliable interpretation of evidence.

Identity attacks are unusually challenging to detect because adversaries frequently operate through legitimate mechanisms.

Users request Kerberos tickets every day.

Administrators modify directory objects.

Applications query LDAP.

Domain Controllers replicate.

Certificates are issued.

Groups change.

Remote management occurs.

Cloud tokens are refreshed.

Service accounts authenticate.

None of those events is inherently malicious.

The detection problem is therefore not simply:

"Did activity occur?"

The better question is:

"Did activity occur in a context that is inconsistent with the expected identity relationship?"

Consider DCSync.

Replication itself is normal.

The abnormal condition may be a non-Domain Controller principal exercising directory replication rights from a system that does not normally perform replication.

Consider Kerberoasting.

Service-ticket requests are normal.

The suspicious pattern may involve a user or workstation requesting unusually large numbers of service tickets for accounts it has never historically accessed, particularly where those accounts use crackable encryption types.

Consider privileged group modification.

Membership changes are normal administrative events.

The security significance depends on who made the change, from which system, under what administrative context, whether the change was expected, and what authority the resulting membership creates.

This is why later detection chapters emphasize correlation, baseline behavior, identity context, effective privilege, expected administrative sources, and relationship awareness.

Good identity detection is not simply event collection.

It is interpretation of trust activity.
