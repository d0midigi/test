# 1.3.2 Basic Windows Familiarity

Readers should be comfortable enough with Windows to recognize its administrative and security vocabulary.

A reader should understand the difference between a local account and a domain account, know that Windows services can execute under different identities, recognize that the Windows registry stores important configuration information, and have at least some familiarity with file permissions, Event Viewer, PowerShell, Command Prompt, and common administrative consoles.

Deep Windows internals knowledge is not required at this point because the book later explains the specific mechanisms that become important to identity security. These include the Local Security Authority (LSA), Local Security Authority Subsystem Service (LSASS), Security Support Provider Interface (SSPI), security tokens, Security Identifiers (SIDs), logon sessions, authentication packages, credential material, Windows privileges, user rights, and security descriptors.

Those concepts matter because Active Directory does not operate in isolation from the Windows security subsystem.

An account may be authenticated by a Domain Controller, but authorization decisions are ultimately enforced through Windows security contexts, tokens, resource permissions, user rights, and security descriptors. Credential material may be associated with domain authentication, but some of that material eventually exists in process memory, registry-backed secrets, cached credential stores, certificate stores, or logon sessions on Windows systems. Group membership may originate in Active Directory, yet the resulting authorization data must still be interpreted by the Windows host or service protecting a resource.

Later offensive chapters exploit this boundary repeatedly.

Credential extraction from LSASS, token manipulation, cached credential access, LSA secret extraction, Pass-the-Hash, Pass-the-Ticket, and remote administrative movement all make more sense once the reader understands how Windows receives, stores, and applies identity information.

The reader therefore needs enough Windows familiarity to follow the environment, but the security model itself will be taught rather than assumed.
