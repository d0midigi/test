# 1.6.2 Tables and Technical Reference Material

Tables are used where comparison is more useful than narrative explanation. Active Directory security contains numerous subjects that become unnecessarily confusing when buried in paragraphs: group scopes, trust types, Kerberos ticket properties, access rights, certificate-template settings, assurance levels, event sources, privileged groups, federation components, and protocol protections among them.

The purpose of the tables is not to reduce complex subjects to cheat sheets. Instead, they establish stable reference points around which the prose can develop the larger security implications.

A table comparing `GenericAll`, `GenericWrite`, `WriteDACL`, and `WriteOwner`, for example, can identify the technical meaning of each right. The surrounding text can then concentrate on why those rights produce different forms of effective control. Similarly, a table of certificate-template properties can show where particular settings reside while the chapter explains how those settings combine into exploitable issuance conditions.

Where the distinction matters, tables also separate what may initially appear to be synonymous concepts. Authentication is separated from authorization. A Discretionary Access Control List (DACL) is separated from the broader Discretionary Access Control (DAC) model. Windows privileges are separated from directory object permissions. Identity assurance is separated from authenticator assurance. A Kerberos PAC is distinguished from similarly named terms used by unrelated authentication technologies.

Those distinctions become increasingly important as the technical depth increases.
