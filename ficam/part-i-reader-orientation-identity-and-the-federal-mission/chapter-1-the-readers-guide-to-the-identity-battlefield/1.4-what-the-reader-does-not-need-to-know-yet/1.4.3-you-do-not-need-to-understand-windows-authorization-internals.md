# 1.4.3 You Do Not Need to Understand Windows Authorization Internals

Active Directory authorization frequently appears confusing because several related but distinct concepts are casually grouped together under the word "permissions."

The book will separate them.

Readers will learn the difference among security principals, Security Identifiers, access tokens, security descriptors, owners, Discretionary Access Control Lists (DACLs), System Access Control Lists (SACLs), Access Control Entries, inherited permissions, explicit permissions, extended rights, user rights, privileges, group-derived authority, and effective access.

The reader is not expected to know these structures before reaching Chapter 12.

That foundation is necessary because many of the most important Active Directory privilege-escalation paths are authorization problems rather than software vulnerabilities.

A principal with `WriteDACL` does not need a memory-corruption exploit to gain additional authority.

A principal with `WriteOwner` may be able to reposition itself within the authorization model.

A principal with `GenericAll` may control the target object through legitimate directory operations.

An attacker who can modify group membership may obtain privilege through ordinary authorization mechanisms.

The security failure is not that Windows ignored the permissions.

The security failure is that Windows honored permissions whose effective consequences were not sufficiently understood or governed.

This is one of the most important concepts in the entire book:

A permission can be functioning exactly as designed and still create a dangerous attack path.
