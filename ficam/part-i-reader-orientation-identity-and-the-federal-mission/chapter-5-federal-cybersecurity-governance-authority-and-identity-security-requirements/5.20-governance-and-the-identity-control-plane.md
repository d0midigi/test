# 5.20 Governance and the Identity Control Plane

## 5.20 Governance and the Identity Control Plane

### 5.20.1 Tier 0 Requires Governance Visibility

{% hint style="info" %}
The complete set of systems capable of controlling enterprise identity should be known to security managers, engineers, assessors, and authorizing personnel.
{% endhint %}

### 5.20.2 Hidden Authority Creates Governance Blind Spots

{% hint style="info" %}
Hypervisors, backups, endpoint-management platforms, automation systems, certificate authorities, and synchronization engines may not appear in traditional identity inventories despite possessing equivalent authority.
{% endhint %}

### 5.20.3 Shared Identity Services Create Common Risk

{% hint style="info" %}
When multiple systems inherit authentication, certificate, federation, or cloud identity from a shared provider, the assurance of that provider affects every relying system.
{% endhint %}

### 5.20.4 Control Inheritance Must Reflect Reality

{% hint style="info" %}
A system can inherit a control only when another component actually implements the relevant protection and the inherited service remains within its authorized and assessed state.
{% endhint %}

### 5.20.5 Authorization Boundaries Must Follow Technical Dependencies

{% hint style="info" %}
Artificially narrow authorization boundaries can conceal upstream identity systems whose compromise would invalidate the security assumptions of the authorized system.
{% endhint %}
