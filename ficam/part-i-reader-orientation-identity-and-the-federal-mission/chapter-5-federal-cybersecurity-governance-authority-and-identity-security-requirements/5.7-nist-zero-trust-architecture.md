# 5.7 NIST Zero Trust Architecture

## 5.7 NIST Zero Trust Architecture

### 5.7.1 NIST Special Publication 800-207

{% hint style="info" %}
NIST Special Publication 800-207 defines a Zero Trust Architecture in which trust is not granted implicitly based on network location or ownership.
{% endhint %}

### 5.7.2 Identity as a Primary Zero Trust Signal

{% hint style="info" %}
User identity, device identity, application identity, authenticator strength, risk, resource sensitivity, and contextual information contribute to access decisions.
{% endhint %}

### 5.7.3 Policy Decision and Policy Enforcement

{% hint style="info" %}
Zero Trust separates the decision to grant access from the mechanism that enforces the decision, making the quality of identity and policy data critical.
{% endhint %}

### 5.7.4 Continuous Evaluation

{% hint style="info" %}
Access may need to be reevaluated during a session when risk, device state, user status, privilege, or security conditions change.
{% endhint %}

### 5.7.5 Zero Trust Does Not Mean Zero Trusted Infrastructure

{% hint style="info" %}
Identity Providers, directories, policy engines, certificate authorities, device-management systems, synchronization platforms, and telemetry sources still form a highly trusted core.
{% endhint %}

### 5.7.6 Identity Compromise Can Defeat Zero Trust

{% hint style="info" %}
A Zero Trust architecture that consumes manipulated identity, device, or policy information can enforce an adversary's decision perfectly.
{% endhint %}
