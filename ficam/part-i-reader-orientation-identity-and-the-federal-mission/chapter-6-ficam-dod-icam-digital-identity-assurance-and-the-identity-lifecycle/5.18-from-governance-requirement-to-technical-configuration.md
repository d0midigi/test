# 5.18 From Governance Requirement to Technical Configuration

## 5.18 From Governance Requirement to Technical Configuration

### 5.18.1 Law

{% hint style="info" %}
Law establishes statutory obligations and governmental responsibilities.
{% endhint %}

### 5.18.2 Executive Direction

{% hint style="info" %}
Executive Orders and presidential directives can establish government-wide priorities and mandatory security objectives.
{% endhint %}

### 5.18.3 Policy

{% hint style="info" %}
Agency and Department policy assigns responsibilities and defines required outcomes.
{% endhint %}

### 5.18.4 Standards

{% hint style="info" %}
Federal standards specify mandatory technical or assurance requirements within their defined scope.
{% endhint %}

### 5.18.5 Security Controls

{% hint style="info" %}
Security controls express the protections that systems must implement and demonstrate.
{% endhint %}

### 5.18.6 Technical Baselines

{% hint style="info" %}
STIGs, SRGs, vendor security guidance where applicable, and approved agency baselines convert broader requirements into configuration states.
{% endhint %}

### 5.18.7 Local Implementation

{% hint style="info" %}
Group Policy Objects (GPOs), registry settings, directory permissions, certificate templates, Conditional Access policies, firewall rules, role assignments, identity workflows, and application configurations become the actual enforcement mechanisms.
{% endhint %}

### 5.18.8 Operational Evidence

{% hint style="info" %}
Logs, scans, configuration exports, test results, assessment records, change records, screenshots, command output, and automated telemetry demonstrate what exists in the environment.
{% endhint %}

### 5.18.9 The Traceability Chain

{% hint style="info" %}
A defensible implementation should allow practitioners to move in both directions: from governing requirement to technical control, and from technical configuration back to the authority requiring it.
{% endhint %}
