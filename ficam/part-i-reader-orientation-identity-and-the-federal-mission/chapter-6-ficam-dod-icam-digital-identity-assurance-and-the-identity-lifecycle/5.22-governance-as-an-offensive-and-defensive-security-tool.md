# 5.22 Governance as an Offensive and Defensive Security Tool

## 5.22 Governance as an Offensive and Defensive Security Tool

### 5.22.1 Offensive Operators Benefit From Understanding Governance

{% hint style="info" %}
Policies, architecture documents, control statements, network diagrams, approved exceptions, and authorization boundaries may reveal where trust is expected to exist and where implementation gaps are likely to appear.
{% endhint %}

### 5.22.2 Defenders Can Use Governance to Identify High-Value Assumptions

{% hint style="info" %}
Requirements reveal what the enterprise claims must always be true: privileged access is restricted, credentials are strongly protected, authentication is logged, trust is scoped, and access is periodically reviewed.
{% endhint %}

### 5.22.3 Assessment Tests the Difference Between Claimed State and Actual State

{% hint style="info" %}
A mature identity assessment does not simply confirm documentation. It determines whether the technical environment behaves as the governing security model expects.
{% endhint %}

### 5.22.4 Adversaries Exploit Exceptions and Forgotten Dependencies

{% hint style="info" %}
Legacy protocols, mission waivers, unsupported applications, emergency accounts, old trusts, and unmonitored connectors often survive because operational exceptions become permanent.
{% endhint %}

### 5.22.5 Governance Can Help Prioritize Attack-Path Remediation

{% hint style="info" %}
When multiple weaknesses exist, federal mission criticality, Tier 0 reachability, control inheritance, active exploitation, system categorization, and identity assurance can help determine which paths must be removed first.
{% endhint %}
