# 4.3.4 Federal Zero Trust Direction

Federal Zero Trust policy provides a useful example of how governance becomes technical architecture.

The federal strategy established through OMB Memorandum M-22-09 did not define Zero Trust as the elimination of networks or as a single security product. It established a government-wide modernization direction organized across Identity, Devices, Networks, Applications and Workloads, and Data, with explicit security objectives and implementation expectations for Federal Civilian Executive Branch agencies. CISA's current Zero Trust Maturity Model continues to reference that strategy, and GSA's federal Zero Trust resources likewise continue to identify M-22-09 as a central implementation reference.

Identity is central to that transition because Zero Trust removes the assumption that network location alone establishes sufficient trust.

That change affects federal Active Directory environments directly.

A user authenticated from an internal workstation should not receive additional trust merely because the workstation resides on an internal network.

A privileged administrator should not be allowed to exercise Tier 0 authority from an arbitrary endpoint simply because the account credentials are correct.

A device should not necessarily be trusted because a computer account exists for it.

A session should not remain indefinitely trusted because authentication succeeded at the beginning.

These ideas do not eliminate Active Directory.

They increase the importance of understanding exactly what Active Directory is asserting.

The directory identifies principals, supplies group and authorization information, participates in Kerberos authentication, maintains machine identity, distributes policy, and remains deeply involved in administrative authority. Zero Trust does not make those functions less important.

It removes some of the environmental assumptions that previously surrounded them.

This distinction is why FICAM and Zero Trust should be treated as complementary rather than interchangeable.

FICAM addresses the disciplined establishment and governance of identity, credentials, access, federation, and lifecycle relationships. Zero Trust changes how continuously and contextually that trust should be evaluated when access is requested and maintained. Current federal FICAM guidance explicitly positions mature ICAM capabilities as foundational to Zero Trust adoption rather than as a competing architecture.

A weakly governed identity does not become trustworthy because it is fed into a Zero Trust policy engine.

A stale privileged account remains stale.

An overprivileged group remains overprivileged.

A compromised certificate remains a valid-looking credential until the trust system rejects it.

A dangerous directory control path remains dangerous even if the network surrounding it has been extensively microsegmented.

Zero Trust changes the conditions under which trust is granted.

It does not eliminate the need to secure the authorities that define identity in the first place.
