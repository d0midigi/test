# 4.6.2 Defense Information Systems Agency

DISA occupies a particularly visible position for DoD practitioners because it provides enterprise information-technology capabilities while also maintaining security implementation resources used throughout the Department.

For many administrators, the most familiar DISA artifacts are STIGs and SRGs.

Their importance is sometimes misunderstood.

A STIG is not the source of the entire cybersecurity requirement. It is an implementation artifact translating broader security requirements into technology-specific configuration guidance. DISA's Cyber Exchange explicitly describes STIGs and SRGs as bridging NIST SP 800-53 and RMF requirements into security configuration guidance for DoD technology.

This makes STIGs enormously valuable to Active Directory engineering.

Instead of leaving each command to decide independently how a Windows security requirement should be configured, a STIG provides a standardized technical baseline.

But standardization does not eliminate architecture.

Passing every applicable STIG check does not prove that no attack path exists.

A Domain Controller may satisfy its platform STIG while an overprivileged backup system retains control over its virtual machine.

LDAP security settings may be correct while a certificate template creates equivalent authentication authority through another mechanism.

Privileged groups may satisfy individual configuration checks while nested membership creates unexpected effective control.

STIG compliance establishes an important baseline.

Identity-security engineering must then evaluate how those baseline-compliant components interact.

DISA also supports systems and capabilities such as eMASS and Assured Compliance Assessment Solution (ACAS), which place it within the practical workflow of authorization evidence, vulnerability management, and technical assessment for many DoD environments.

That operational integration is one reason DoD practitioners experience governance differently from those reading the policy from the outside.

The same environment is simultaneously being engineered, assessed, documented, scanned, monitored, and authorized.
