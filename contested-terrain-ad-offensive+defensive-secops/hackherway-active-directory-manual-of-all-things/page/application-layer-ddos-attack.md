# Application Layer DDoS Attack

\### What is an Application Layer DDoS Attack?

An application layer DDoS attack, also known as a layer 7 (L7) DDoS attack, targets the "top" layer of the OSI model where common internet requests such as HTTP GET and HTTP POST occur. Unlike network layer attacks like DNS amplification, application layer attacks are particularly effective because they consume both server resources and network resources.

\### How Do Application Layer Attacks Work?

The effectiveness of most DDoS attacks lies in the imbalance between the resources required to launch an attack and the resources needed to mitigate it. This is especially true for L7 attacks, which can disrupt both the targeted server and the network with relatively low bandwidth. An application layer attack can cause significant damage with less total bandwidth.

To understand this, consider the resource disparity between a client making a request and a server responding to it. When a user logs into an online account, such as Gmail, the user's computer uses minimal resources compared to the server, which must check login credentials, load user data from a database, and send back the requested webpage. Even without a login, a server often needs to make database queries or other API calls to generate a webpage.

When many devices simultaneously target a single web property, as in a botnet attack, the resource disparity is magnified. This can overwhelm the targeted server, resulting in denial-of-service to legitimate traffic. In many cases, simply targeting an API with an L7 attack is enough to take the service offline.

\### Why is it Difficult to Stop Application Layer DDoS Attacks?

Stopping application layer DDoS attacks is challenging because it is hard to distinguish between malicious traffic and normal traffic. In an application layer attack, such as a botnet performing an HTTP Flood attack, each bot makes legitimate-looking network requests. This traffic is not spoofed and often appears normal in origin.

To counter these attacks, an adaptive strategy is required, which includes the ability to limit traffic based on specific rules that may change frequently. Tools like a properly configured Web Application Firewall (WAF) can help mitigate bogus traffic, reducing the impact on the origin server.

For other types of attacks, such as SYN floods or reflection attacks like NTP amplification, strategies can efficiently drop the traffic if the network has the bandwidth to handle it. However, most networks cannot handle a 300Gbps amplification attack, and even fewer can manage the volume of requests generated by an application layer attack. This makes L7 attacks particularly difficult to defend against.

\### Tactics to Mitigate Application Layer Attacks

1\. \*\*Implement Challenges\*\*:

\- \*\*CAPTCHA\*\*: Use CAPTCHA tests to differentiate between human users and bots. This common approach can effectively block automated traffic.

\- \*\*JavaScript Computational Challenges\*\*: Require devices making network requests to solve a JavaScript challenge. This can filter out many bot attacks as most bots will not execute JavaScript.

2\. \*\*Web Application Firewall (WAF)\*\*:

\- Deploy a WAF to monitor, filter, and block HTTP traffic to and from a web application. A properly configured WAF can identify and mitigate malicious traffic while allowing legitimate traffic to pass through.

3\. \*\*IP Reputation Database\*\*:

\- Utilize an IP reputation database to filter traffic based on known malicious IP addresses. Blocking or limiting requests from these IPs can prevent malicious bots from overwhelming the server.

4\. \*\*On-the-Fly Network Analysis\*\*:

\- Conduct real-time network analysis to detect and respond to suspicious traffic patterns. Engineers can use this analysis to implement adaptive measures that mitigate ongoing attacks.

By combining these tactics, organizations can enhance their defenses against application layer attacks and reduce the risk of service disruption.

Application layer Denial of Service (DoS) attacks exploit vulnerabilities in protocol implementations or designs. Unlike volumetric DoS attacks, these are stealthy and target specific applications running on the victim's system. Numerous attacks have been discovered against popular application layer protocols in recent years. This paper offers a structured and comprehensive survey of existing application layer DoS attacks and defense mechanisms. We categorize the various attacks and defenses, explain their functionality, and compare them based on relevant parameters.
