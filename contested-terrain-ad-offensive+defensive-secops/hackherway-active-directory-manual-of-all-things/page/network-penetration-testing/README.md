# Network Penetration Testing

Network Penetration Testing

Definition and Purpose

Penetration testing is the process of assessing and evaluating the security posture of computer and network systems by discovering vulnerabilities and attempting to break into these systems.

Another term for _penetration testing_ is _ethical hacking._ Penetration testers are called _ethical hackers_ or _white hat hackers._ On the other hand, _unethical hackers_ are called _black hat hackers._ The only difference ethical hacking and unethical hacking is the consent of the target; that is, in ethical hacking, e.g., penetration testing, the target has given written permission to the ethical hacker to perform such tests for the purpose of evaluating and assessing security posture levels.

Penetration testing can reveal to you a lot about what the network infrastructure holds and what and how hackers may compromise or damage network components. By conducting penetration testing on these network components, the target organization can obtain insightful information like:

* Vulnerabilities or weaknesses in systems
* How these uncovered vulnerabilities can be exploited
* The damage and impact that may result from such exploitation
* How to remediate and eliminate critical security vulnerabilities

**Information Security**

Any business relies on information such as trade secrets, customer data, financial documents, emails, and more. Information Security revolves around preserving the _**Confidentiality, Integrity,**_ and _**Availability**_ (C.I.A. triad) of business information:

* **Confidentiality** means that the information is accessed only by authorized personnel with a need-to-know. It pertains to the secrecy of that information. If by any means the information was accessed in an unauthorized manner, confidentiality has been breached.
* **Integrity** means that information is not modified or changed accidentally or intentionally by unauthorized persons. It pertains to the accuracy – or correctness – of that information. If by any means the information was modified by an unauthorized person, the integrity has been breached.
* **Availability** means that the information must be available upon demand anytime, anywhere. If the information is fully or partially lost, or rendered inaccessible to authorized persons, the availability has been breached.

Later when we talk further about vulnerabilities, we will learn that the risk value of any vulnerability is calculated based on how this vulnerability affects the Confidentiality, Integrity, and Availability of the system.

Preserving the CIA of information is done by implementing certain security mechanisms, called Controls. There are two categories of security control mechanisms: Process Controls, and Interactive Controls.

1. **Process Controls:** These are security mechanisms applied directly to information that needs protection. The information is processed in certain ways – by these controls – so that the CIA are preserved. The process controls contain _**Encryption, Hashing/Digital Signature,**_ and _**Backup:**_
   1. **Encryption:** Encryption is used to preserve the confidentiality of information, and it is the process of ciphering the actual information using a “key.” The output code is called _**ciphertext.**_ Only those who possess the decryption key can decrypt the ciphertext to read the original message. It is important to note here that encryption cannot be accomplished without a corresponding key. Some people confuse mere encoding or encryption. Encoding does hide the original text into a code; however, an encoded message can be reversed by anyone who knows the encoding algorithm. With encryption, no one can decrypt the ciphertext even if they know the encryption algorithm. The “key” must be known to the party decrypting the ciphertext. Examples of encryption algorithms are DES, AES, and RSA.
   2. _**Hashing and Digital Signatures:**_ Hashing is used to preserve the integrity of information; and it is the process of generating a unique fingerprint (a string) of fixed length of the information. A hashing algorithm takes the original text as an input, and then calculates a fixed-length code; the output code is always the same as long as the input text is the same. If one bit is changed in the input, a totally new hash will be generated. An important point to mention here is that unlike encryption, we cannot get the original text from the hash; in other words, hashing algorithms cannot be reversed. They produce hashes from original texts, but cannot get the original texts from hashes. That is why a hashing algorithm is called a _**one-way hash.**_ A digital signature guarantees the integrity of the original text; in addition, it attests to who the actual data or system owner is. Examples of hashing algorithms are MD5, SHA1 and SHA2.
   3. _**Backup:**_ This process preserves the availability of information, and it is the process of making one or more copies of the information – whether the original text or the ciphertext – that are kept in a secure location different from the location of the original information. In this case, of the original information is lost, it can be restored from previous backups.
2. _**Interactive Controls:**_ These controls are implemented as measures when the information – to be secured – interacts with external entities. They are not applied to how the information is processed (like in Process Controls), rather they are applied whenever another entity (like a system or a person) attempts to interact with the information. There are three such controls and they are _**Authentication, Authorization,**_ and _**Accounting (AAA).**_
   1. _**Authentication:**_ The mechanism of determining if an individual – a system or a person – is allowed to access the protected space; the space can be a physical location, a software application, or any other system. The most common form of authentication is _password_ authentication that most people are familiar with. When you log into your Facebook account with a username and password, that is authentication; however, there are three ways to implement authentication:
      1. What the user knows – like a password or a passphrase
      2. What the user has – a PIN or access card
      3. What the user is – Biometrics: fingerprints, vocal patterns
   2. _**Authorization:**_ This is the mechanism of determining what an individual is allowed to do _after_ they have been authenticated. Authorization is about the access rights and privileges they have. If we take Facebook for example, authorization relates to the actions that you are allowed to do after you successfully log in; what photos are you allowed to view? Which people are you allowed to comment back on their walls? When it comes to files within systems, which files are you allowed to read, modify, or delete? Privileges given to different, legitimate, and authenticated users are part of the authorization mechanism.
   3. _**Accounting:**_ This is the mechanism of logging and reviewing all actions and attempts by users. Accounting reveals any unauthorized attempts. It is a way to track what is being done and by whom to expose any misuse.

In short, the security of a certain information revolves around preserving its Confidentiality, Integrity, and Availability (CIA). Confidentiality is maintained by Encryption, Integrity is maintained by Hashing or Digital Signature, and Availability is maintained by Process Controls. In addition, while external entities interact with the information, we need three additional controls – called _**Interactive Controls**_ – and contain _**Authentication, Authorization,**_ and _**Accounting (AAA).**_

As business rely on computer and network systems for day-to-day operations, these systems must be operating as intended with little to no interruption – as in Denial of Service (DoS) attacks. Also, publicly exposed systems, like websites, must be secured and protected.

**Vulnerabilities, Threats, and Exploits**

There are three main terms that you should expect to see repeated often within ethical hacking lexicon; and these are _**vulnerability, threat,**_ and _**exploit.**_ It is very important to understand these terms and their nuances.

* **Vulnerability** is a weakness in the hardware or software which can be taken advantage of by a malicious actor, thus reducing the overall assurance of information. It is a hole in the overall security of the system. Vulnerabilities are the entry points through which hackers find their way into a system. During a penetration test, there is a phrase called “Vulnerability Assessment,” during which the penetration tester attempts to find all vulnerabilities in the target systems and networks, assesses their potential harm, and ultimately recommends to the client organization the practical solutions to remediate or mitigate those vulnerabilities.
* **Threat** is any dangerous agent that can take advantage of a vulnerability or break through it; a threat is potentially a source of harm to a system or network. A threat can be human, like hackers, technical like viruses and worms, or natural disasters, like floods and earthquakes.
* **Exploits** are software codes implemented and used by hackers to take advantage of, or exploit, a vulnerability. Exploitation seeks to create an unintended behavior in remote systems that yields a system compromise. Exploitation is the “clever” way to enter the system through the use of a security gap, weakness, or flaw of a vulnerability. Whenever there is a vulnerability, hackers, both ethical and unethical, think outside-the-box to exploit these weaknesses found in systems. The practical means of exploitation is implemented into code which is called an “exploit.” During a penetration test, the tester tries to exploit discovered vulnerabilities and reveal to the client the actual harm that may result in the event vulnerabilities remain unfixed.

We can better understand these terms if we look at the following analogy. Let’s say there is a house that has something valuable inside of it, yet its door has a weak lock. In such a scenario, the weak lock might be called a vulnerability, a thief who might break into the house would be a threat, while the master key or the tool used by the thief to break the weak locking mechanisms might be called an exploit.

**Risk Assessment and Impact Analysis**

When it comes to information security in any business, there is always the question of how much to invest to mitigate and close vulnerabilities. Because higher security would require a higher budget; thus, executive management would ask questions like how much budget would be necessary to achieve the desired technical security implementations? To come up with the right answer, additional assessments are needed. Just mere vulnerability assessment is simply not enough. A business needs to conduct these two critical processes:

1. **Risk Assessment** is an evaluation of the likelihood of harm that can occur; that is, risk asks the question, _“what is the likelihood that a certain vulnerability gets exploited?”_ There might be a certain vulnerability that the organization is aware of, yet, if the likelihood of its exploitation is low, then, there is a low risk coming from it. ON the other hand, if the likelihood of its exploitation results as a high security threat, then, the risk is high. Visiting our previous analogy of the house with a weak locking mechanisms, if the house is in a neighborhood which is known for frequent crimes and theft, then that risk is considered high. A business must conduct a Risk Assessment for each identified vulnerability to assess the associated risk levels.
2. **Impact Analysis** identifies the actual damage that might result from a harmful incident; that is, once a vulnerability is exploited, the damage that results – such as financial losses, leaked sensitive information, loss of reputation, to name a few -= is the impact of that incident. Impact analysis determines how much possible damage can occur if each vulnerability were to be exploited. Visiting our house analogy, if there is $100,000 worth of gold in the house that could be stolen in case of theft, then, we can say the impact is high; however, on the other hand, if the house is merely empty, then the impact is considered low.

Based on the outcomes of Risk Assessment and Impact Analysis, management can make a better judgment whether to mitigate a certain vulnerability or not; and, if so, how much should be invested in implementing such mitigations? Let’s look again at the house analogy and consider these four scenarios:

1. If the risk is deemed _high_ and the impact is deemed _high_, then it is worth investing in an expensive, high-quality lock.
2. If the risk is deemed _low_ and the impact is also deemed _low_, then we might not do anything about the lock. We can opt to accept the situation as it is.
3. If the risk is deemed _high_, and the impact is _high_; just like in the previous case, might opt to just buy a medium quality locking mechanism.
4. If the risk is deemed _low,_ but the impact is _high_; just as in the previous case, we might opt to buy a medium quality locking mechanism.

**Types of Categories and Penetration Testing**

There are different ways to categorize the different types of penetration testing. One way is to look at how much knowledge an ethical hacker has about their targets prior to staring the actual penetration test. Another way is to consider the location from which the hacker will conduct the penetration test. The following two sections describe these categories:

**Black Box vs. White Box Penetration Tests**

When the ethical hacker conducts a penetration test with no prior knowledge about the target, such a test is called a black box text. On the other hand, if the hacker has full knowledge about the target, it is called a white box test.

Many varying reasons exist as to why an organization might request one test over another. A black box test simulates how the hacking process of “real-world” hackers would be enacted upon since hackers are most likely to perform their activities shrouded in anonymity and sometimes without conscious interaction with their targets; however, a black box test may miss certain vulnerabilities if there are systems or applications that are completely hidden yet could not be discovered during the timeframe of the test. This can be both a good and a bad thing. Good because you’ve situated critical systems in such a way that they’re well hidden in a network either through segmentation or VLAN’ing making it all the more difficult of a time for both ethical and unethical hackers to discover; a bad thing because, well, if those hidden systems remain hidden and unchecked or unscanned for various periods, could mean they house extreme critical severities with no attention set forth towards remediating them. They can be lying dormant for all one knows. Because of this factor, a black box test is usually a faster testing process than its counterpart and costs less due to time, resources, and padding for unforeseen events happening related to the penetration testing.

**Budget Padding for Unforeseen Events**

**It’s always a good idea for management to have a financial reserve or a pot, or bucket of “extra money,” lying around in case of unforeseen events that may happen during a penetration test. For example, a network I was testing against, a Cisco router I was manually checking the IOS running configuration settings, and upon launching a Retina scan against its running config, the power supply (both of them) decided to go kaput, meaning the router completely died in the middle of testing from the scan. Now, call it a fluke, as a virtual scan should have no impact on a physical component such as a power supply for a router failing, but it happened. Luckily, the company had a warranty for the Cisco router that covered failed parts, and we were able to the receive the replacements within a four-hour window. We installed them and I was backup scanning in no time. This is exactly a justifiable case for the importance for management to have a backup of reserved funds to provide padding against unforeseen disruptions and situations that may arise much like the one I experienced.**

Between the two extremes, a combination of both types comes in the middle and it is called a Gray Box test. This test provides the tester with partial knowledge about the target network. Gray box testing is pretty much the best of both worlds, combining elements of both black- and white-box testing procedures.

**External vs. Internal Penetration Tests**

When considering the location from which the penetration test originates, you will find that for any target organization, a tester can be located inside the organization’s Local Area Network (LAN), or located anywerhe external to the atrget’s LAN and conduct the pentests over the Internet. Accordingly, a penetration test can be an external test or an internal test.

An external penetration test is conducted over the Internet, assesses the Internet presence of the target. That is, the ethical hacker attempts to break into the target through their public, Internet-facing systems. It simulates external black hat hackers who can be located anywhere in the world. An external test generally assess security postures for systems like:

* DNS Servers
* Web (HTTP/HTTPS) Servers
* File (FTP) Servers
* Remote Access (VPN/Citrix/RDP/SSH/RADIUS/DIAMETER/RAS P2P) Servers
* Mail (SMTP/IMAP/POP3) Servers
* Routers and VPN Gateways
* Firewalls, IDS/IPS, and Honeypots

Conversely, an internal penetration test is done from within the local perimeter of the target organization. It primarily simulates the hacking process of a malicious insider; that is, a disgruntled employee possibly, or a third-party contractor who is supposed to be trusted by the organization yet has malicious intent. This type of penetration test generally involves the following actions:

* Traffic eavesdropping and session hijacking
* Confidential information harvesting and gathering such as documents containing PII
* Obtaining local and global group and user administrative privileges
* Exploiting internal SQL and web database servers
* Exploiting internal email relays and gateway servers
* Exploiting internal FTP and SSH servers (which should be placed in a DMZ)
* Assessing wireless network security

**Methodologies and Standards**

To standardize the process of ethical hacking, different organizations have created comprehensive methodologies that outline all the steps and phases of the ethical hacking and penetration testing processes. These methodologies and standards provide frameworks for hackers and testers to follow during the course of their penetration testing engagements or a hacking security assessment, so that the test is comprehensive and complete. Also, these methodologies and standards provide the target organizations with knowledge to evaluate the depth and accuracy of a third-party penetration test. Thus, methodologies help both the ethical hacker as well as the target to get the best out of their penetration testing endeavors.

In this section, we look at five different methodologies and standards, to include:

1. Open Source Security Testing Methodology Manual (OSSTMM)
2. Penetration Testing Execution Standard (PTES)
3. NIST Technical Guide to Information Security Testing and Assessment
4. Penetration Testing Framework (PTF)
5. Open Web Application Security Project (OWASP) Testing Guide

**1. The Open Source Security Testing Methodology Manual (OSSTMM)**

_**(Source:**_

The OSSTMM was developed by the Institute of Security and Open Methodologies (ISECOM) in January 2001, by Pete Herzog, and since then, many researchers have contributed to it. According to their website: _“it is a peer-reviewed manual for security testing and analysis which results in verified facts. These facts provide actionable information that can measurably improve your operational security. \[…] The OSSTMM is about operational security. It is about knowing and measuring how well security works.”_

The OSSTMM takes into consideration the interactions between people, processes, systems, and software. Further, it seeks to test the securities of five domains in any business, which are the human, the physical, the wireless, the telecommunications, and the data networks; each domain is called a _**channel.**_ The following table taken from the OSSTMM, explains these five domains, or channels:

| **Class**                        | **Channel**                                                                                                                                                                                                              | **Description**                                                                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Physical Security (PHYSSEC)      | **Human**                                                                                                                                                                                                                | Comprises the human element of communication where interaction is either physical or psychological.                                                                                                                           |
| **Physical**                     | Physical security testing where the channel is both physical and non-electronic in nature. Comprises the tangible element of security where interaction requires physical effort or as energy transmitter to manipulate. |                                                                                                                                                                                                                               |
| Spectrum Security (SPECSEC)      | **Wireless**                                                                                                                                                                                                             | Comprises all electronic communications, signals, and emanations which take place over the known EM spectrum. This includes: ELSEC (Electronic Communication), SIGSEC (Signals), and EMSEC (Emanations untethered by cables). |
| Communications Security (COMSEC) | **Telecommunications**                                                                                                                                                                                                   | Comprises all electronic systems and data networks where interaction takes place over established cable and wired network lines.                                                                                              |
| **Data Networks**                | Comprises all electronic systems and data networks where interaction takes place over established cable and wired network lines.                                                                                         |                                                                                                                                                                                                                               |

The OSSTMM has its advantages and disadvantages. The most obvious advantage of the OSSTMM is that it is thorough. The OSSTMM covers all aspects of information security, including the human/personal and the physical aspects. Most of the methodologies available focus on the technical side of penetration testing, that is, testing data, networks, and systems. The OSSTMM covers a complete approach to social engineering and testing the physical securities of an organization.

However, the OSSTMM guide does not tell you which tools ot use to accomplish a particular task. The lack of technical instruction is its disadvantage – especially if you are a beginner to penetration testing and if you are looking for such type of information. It simply instructs the tester about what needs to be done but doesn’t really explain how it should be done. It is up to you which tools to use, and it is your job to find the right tools for each task. For this reason, some people find the OSSTMM to be too theoretical, conceptual, yet non-practical – unlike the second standard, the PTES.

As mentioned above, the OSSTMM covers five domains (channels) to test and audit; the following is a summary of each channel:

1. **Human Security Testing:** Human security testing in the OSSTMM (Open Source Security Testing Methodology Manual) involves evaluating the human element in security, focusing on how individuals interact with security protocols and systems. This testing examines vulnerabilities such as social engineering, insider threats, and the effectiveness of training programs. It assesses how well employees follow security procedures, their susceptibility to manipulation, and their ability to recognize and respond to security incidents. The goal is to identify weaknesses in the human aspect of security that could be exploited, ensuring that personnel are adequately prepared and that policies are effectively enforced to protect organizational assets.
2. **Physical Security Testing:** Physical security testing in the OSSTMM (Open Source Security Testing Methodology Manual) focuses on evaluating the effectiveness of physical controls in protecting assets from unauthorized access or harm. This testing involves assessing barriers like locks, fences, surveillance systems, and access controls, as well as the response to breaches or intrusions. The goal is to identify vulnerabilities in the physical security infrastructure that could be exploited by attackers, ensuring that the physical measures in place are robust and effective. By adhering to OSSTMM guidelines, testers provide organizations with a comprehensive analysis of their physical security posture and recommendations for improvement.
3. **Wireless Security Testing:** Wireless security testing in the OSSTMM (Open Source Security Testing Methodology Manual) involves assessing the security of wireless networks to identify vulnerabilities that could be exploited by unauthorized users. This process includes examining signal leakage, encryption strength, authentication mechanisms, and access controls. The goal is to evaluate the resilience of the wireless infrastructure against various attacks, such as eavesdropping, man-in-the-middle, and unauthorized access. By following OSSTMM guidelines, testers ensure a thorough evaluation of wireless networks, providing organizations with insights into potential security weaknesses and recommendations for enhancing wireless security.
4. **Telecommunications Testing:** This focuses on assessing the security of voice and data communication systems. It involves evaluating the infrastructure, such as switches, routers, and PBX systems, as well as the protocols used for transmitting information. The goal is to identify vulnerabilities that could lead to unauthorized access, interception, or disruption of communications. This testing ensures that communications channels are secure, resilient, and compliant with industry standards, helping to safeguard sensitive information and maintain the integrity of telecommunications systems.
5. **Data Network Security Testing:** This testing involves a comprehensive assessment of a network’s infrastructure to identify vulnerabilities that could compromise the confidentiality, integrity, and availability of data. This testing covers aspects like network topology, firewalls, routers and switches, along with the protocols and services running over the network. By simulating real-world attacks, the testing uncovers potential weaknesses in the network, such as misconfigurations, outdated software, or insecure communications channels.

**2. The Penetration Testing Execution Standard (PTES)**

The Penetration Testing Execution Standard (PTES) is a comprehensive framework that guides the entire process of penetration testing, from pre-engagement interactions to post-exploitation reporting. It standardizes methodologies for ethical hackers to follow, ensuring consistency and thoroughness in identifying and exploiting vulnerabilities in systems and networks. PTES covers key stages like information gathering, threat modeling, vulnerability analysis, exploitation, post-exploitation, and reporting, offering a structured approach to assessing and improving an organization's security posture. The goal is to provide clear, actionable results that help organizations address security gaps effectively.

This comprehensive technical standard encompasses all the key phases and critical steps of a professional penetration test. It is further bolstered by a technical guideline featuring 33 security tools, each linked to their respective parent websites. The PTES (Penetration Testing Execution Standard) breaks down the penetration testing process into seven distinct phases:

**1. Pre-engagement Interactions:** During pre-engagement interactions, it is crucial to lay down the groundwork by defining the scope, objectives, and rules of engagement. This initial phase aims to establish a common understanding between the tester and the client regarding the goals that need to be achieved, the areas to be tested, and the guidelines that will shape the testing process. By outlining these key aspects upfront, both parties can align their expectations and ensure that the testing activities are carried out effectively and efficiently. This phase also provides an opportunity to clarify any uncertainties, address any potential issues, and set the stage for a productive collaboration moving forward. Overall, pre-engagement interactions serve as the foundation for a successful testing engagement by laying out a clear roadmap that guides the testing process and sets the tone for a constructive partnership between the tester and the client.

**2. Intelligence Gathering:** Intelligence gathering is a critical stage in the process of conducting a thorough and comprehensive assessment of a target environment. This crucial step involves meticulously collecting a wide range of data points that provide valuable insights into the network infrastructure, domain names, and potential vulnerabilities present within the target system. By systematically identifying network ranges, domain names, and possible areas of weakness, cybersecurity experts can effectively arm themselves with the necessary information to assess the overall security posture of the target environment. Through thorough intelligence gathering, analysts can gain a deeper understanding of the target's digital landscape, enabling them to pinpoint potential entry points and exploit scenarios. This meticulous data collection effort plays a pivotal role in shaping subsequent phases of the cybersecurity assessment, helping to streamline the identification of critical assets, prioritize security measures, and develop targeted strategies to address vulnerabilities effectively. Overall, intelligence gathering acts as the foundational building block that empowers cybersecurity professionals to make informed decisions and execute precise actions aimed at enhancing the security resilience of organizations and countering potential threats effectively.

**3. Threat Modeling:** In the phase known as Threat Modeling, a comprehensive examination of the intelligence gathered is conducted in order to meticulously pinpoint potential threats that could pose risks to a system's security. This process involves examining the data to uncover the vulnerabilities that malicious actors may leverage to launch attacks.

Two key elements must be identified in this phase: 1. Assets, and 2. Threats. Assets are the systems and/or applications owned by the target, while threats are the dangers that can potentially corrupt or compromise the assets. Threat Modeling is done through four steps:

* **Step 1:** Gather relevant information
* **Step 2:** Identify and categorize primary and secondary assets
* **Step 3:** Identify and categorize threats
* **Step 4:** Map threats against assets

Threat Modeling essentially serves as a strategic mechanism to anticipate and prepare for potential cyber threats by foreseeing the various attack vectors that could be exploited by threat actors. By scrutinizing the intelligence gathered through this process, organizations can enhance their ability to pre-emptively address and mitigate potential security risks.

**4. Vulnerability Analysis:** In the process of conducting Vulnerability Analysis, it is crucial to systematically approach the task of identifying and verifying potential security vulnerabilities within the target systems. This involves skillfully leveraging a combination of automated tools and manual techniques to thoroughly assess and validate the security posture of the systems under scrutiny. By carefully scrutinizing the systems through meticulous examination, both automated scanning software and manual inspection methods are utilized to comprehensively detect and confirm any potential weaknesses that could be exploited by malicious actors. This comprehensive approach not only helps in uncovering existing vulnerabilities but also plays a key role in evaluating the overall security resilience of the systems, providing valuable insights for enhancing their protection mechanisms. Through the utilization of advanced automated tools and the expertise of manual analysis, vulnerabilities are systematically pinpointed and verified, ensuring a robust and rigorous examination process that aims to fortify the security defenses of the target systems. By bridging the gap between automated scanning capabilities and human intuition, the Vulnerability Analysis process becomes a dynamic and multifaceted endeavor that is essential in safeguarding against potential cyber threats and fortifying the security posture of the systems to withstand evolving malicious tactics and techniques.

**5. Exploitation:** Exploitation involves the deliberate act of utilizing known vulnerabilities to breach security measures for the purpose of gaining illicit access to systems or networks. This nefarious practice entails a strategic effort to uncover weaknesses, execute attacks, and reveal the potential consequences that these vulnerabilities might pose. By exploiting security gaps, threat actors seek to infiltrate defenses, compromise sensitive information, and gauge the extent of the risks inherent in the targeted systems. Therefore, exploitation acts as a critical component in the process of evaluating security posture, as it sheds light on the effectiveness of protective measures and highlights areas that require urgent attention to prevent potential breaches and safeguard valuable assets against malicious intrusions. Through exploiting vulnerabilities, security professionals can simulate real-world scenarios, assess the impact of potential cyber threats, and fortify defenses through the implementation of proactive measures aimed at reducing exposure to security risks. Ultimately, the act of exploitation serves as a necessary exercise in understanding the vulnerabilities present within systems and reinforces the importance of maintaining a vigilant and resilient security infrastructure in the face of evolving cyber threats.

**6. Post-Exploitation:** Post-Exploitation involves a crucial phase where the cyber attacker meticulously evaluates the worth of the compromised systems. This assessment is vital as it helps the attacker understand the potential benefits and risks associated with the breach. Moreover, beyond just assessing the systems, the attacker aims to ensure continuous access to the compromised network. By maintaining this foothold, the attacker can delve deeper into the organization’s infrastructure, actively seeking out additional vulnerabilities that may exist. This thorough examination of the system allows the attacker to map out a comprehensive strategy to escalate the breach and access more critical data. Furthermore, the attacker's objective during this phase extends to uncovering any sensitive information that could be of significant value or potentially damaging to the organization. Through persistent penetration efforts, the attacker aims to exploit these newly discovered vulnerabilities to infiltrate deeper into the network, maintaining a level of persistence that ensures prolonged access. Ultimately, this post-exploitation phase serves as a critical juncture in the cyber attacker's overall strategy, enabling them to maximize the impact of the breach and extract valuable data to achieve their malicious objectives.

**7. Reporting:** In the process of reporting, it is imperative to meticulously document all findings discovered during the security assessment. This documentation should not only outline the vulnerabilities identified but also provide in-depth explanations regarding their nature, scope, and potential consequences if exploited by malicious actors. Furthermore, it is crucial to clearly outline the impact these vulnerabilities could have on the client's overall security posture and operational continuity.

Moreover, the reporting should not stop at merely listing the vulnerabilities but should also detail the specific actions that can be taken to address and remediate each identified issue effectively. By providing detailed and actionable recommendations, the client can gain a comprehensive understanding of the necessary steps to strengthen their security defenses and mitigate potential risks effectively.

Overall, the ultimate goal of the reporting process is to empower the client with the knowledge and insights needed to make informed decisions about their security strategy and prioritize remediation efforts accordingly. By presenting a thorough and well-documented report, the client can better comprehend the implications of the security vulnerabilities and confidently navigate the necessary next steps to enhance their overall security posture.

**3. The National Institute of Standards and Technology (NIST) Technical Guide to Information Security Testing and Assessment (SP 800-115)**

_**(Source:**_

The National Institute of Standards and Technology (NIST) Technical Guide to Information Security Testing and Assessment (SP 800-115) provides a comprehensive framework for organizations to evaluate and enhance their information security practices. This guide outlines various testing and assessment methodologies, including vulnerability assessments, penetration testing, and security audits, to identify and mitigate potential security risks.

The guide describes these four phases to penetration testing as follows:

* _**Planning:**_

This phase includes preparatory actions, meetings, and conversations with the client. Basically, it covers the following aspects:

1. Identifies Rules of Engagement
2. Obtains management approvals
3. Sets the goals of the type of testing to be performed

* _**Discovering:**_

This phase includes the first portion of the engagement (e.g., the penetration test). The aim here is to know all vulnerabilities, weaknesses, holes, and entry points so that an accurate attack plan can be devised. The discovering phase is further divided into the following parts:

1. Information Gathering
2. Scanning
3. Vulnerability Analysis

* _**Attack:**_

This is the phase of executing the attack plan. This phase reveals all the harms, with their proofs, that can be done to the target. According to the guide, this phase involves four primary actions:

1. Gaining Access
2. Escalating Privileges
3. System Browsing
4. Installing Tools

* _**Reporting:**_

The last phase is to write a report explaining and detailing the findings, mitigations strategies, and solutions. The actual time of delivering the report must be agreed upon during the first phase, the Planning phase.

The PTES emphasizes the importance of a structured approach, starting with the planning phase, where objectives and scope are defined, followed by execution, where the tests are performed using appropriate tools and techniques. The results are then analyzed, documented, and reported to inform decision-making and improve the organization's overall security posture. The guide also stresses the need for continuous improvement and regular testing to adapt to evolving threats.

The Penetration Testing Framework (PTF) is an open-source framework designed to streamline and standardize the process of penetration testing. It provides a modular platform that integrates a wide range of security tools and techniques, allowing testers to efficiently conduct assessments and manage their toolsets. PTF supports automation and customization, enabling users to easily deploy and update tools, customize testing environments, and generate comprehensive reports.

Furthermore, the PTF covers the following aspects:

* _**Network Footprinting (Reconnaissance):**_ Network Footprinting, also known as reconnaissance, within the Penetration Testing Framework (PTF) involves gathering detailed information about a target network to identify potential vulnerabilities and attack vectors. This phase utilizes a variety of tools and techniques to collect data such as IP addresses, domain names, network architecture, and open ports. By leveraging automated scanners and manual methods, testers build a comprehensive map of the network, which is crucial for understanding its structure and security posture. The insights gained from network footprinting guide subsequent phases of the penetration test, enabling testers to craft targeted strategies for vulnerability assessment and exploitation.
* _**Discovery, Probing and Enumeration:**_ In the Penetration Testing Framework (PTF), Discovery, Probing, and Enumeration are critical phases for identifying and mapping out the target's network resources and services. Discovery involves the initial phase of gathering basic information about the network, such as IP addresses and active hosts. Probing follows with more in-depth interaction to detect open ports and active services on these hosts. Enumeration then delves deeper, extracting detailed information about the network services, including user accounts, shared resources, and network configurations. This structured approach allows penetration testers to build a comprehensive picture of the target environment, pinpointing potential vulnerabilities and attack vectors for further analysis and exploitation.
* _**Password Cracking:**_ In the Penetration Testing Framework (PTF), password cracking is a crucial phase focused on deciphering password hashes to gain unauthorized access to systems. This process involves using specialized tools and techniques to attempt to break encrypted or hashed passwords through methods such as brute force, dictionary attacks, and rainbow tables. By exploiting weak or poorly chosen passwords, testers can demonstrate the potential risks of inadequate password security and assess the robustness of the target’s authentication mechanisms. Successful password cracking provides insights into the effectiveness of password policies and highlights areas where stronger security measures are needed.
* _**Vulnerability Assessment:**_ In the Penetration Testing Framework (PTF), vulnerability assessment involves systematically identifying, analyzing, and evaluating security weaknesses within a target system or network. This phase utilizes automated scanning tools and manual techniques to detect vulnerabilities such as outdated software, misconfigurations, and exposed services. The goal is to compile a comprehensive list of potential security issues, prioritize them based on their severity and potential impact, and provide actionable recommendations for remediation. By conducting a thorough vulnerability assessment, testers can help organizations understand their security posture, address critical weaknesses, and strengthen their defenses against potential attacks.

* _**Penetration:**_ In the Penetration Testing Framework (PTF), the penetration phase involves actively exploiting identified vulnerabilities to gain unauthorized access or control over systems. This phase tests the effectiveness of existing security measures by simulating real-world attacks, including exploiting weaknesses in software, network configurations, or user practices. Penetration testers use a combination of manual techniques and automated tools to execute attacks, escalate privileges, and access sensitive information. **5.. The Open Web Application Security Project (OWASP)**

The Open Web Application Security Project (OWASP) is a nonprofit organization dedicated to improving software security by providing open-source tools, resources, and best practices. OWASP focuses on enhancing the security of web applications and online services through community-driven projects, including the widely recognized OWASP Top Ten list, which highlights the most critical security risks to web applications.

The guide discusses the following phases:

* _**Information Gathering:**_ In OWASP's context, information gathering is a crucial phase in the security assessment process, where the goal is to collect as much data as possible about a target application or system to identify potential vulnerabilities. This process involves various techniques, including passive methods like reviewing public information, domain registration details, and network infrastructure, as well as active methods such as scanning for open ports and services. By aggregating and analyzing this information, security professionals can build a detailed profile of the target, which helps in uncovering weaknesses and planning more effective security tests. This phase is foundational for developing a comprehensive understanding of the security posture of web applications and ensuring robust protection against potential attacks.
* _**Configuration and Deployment Management Testing:**_ Configuration and Deployment Management Testing, within the OWASP framework, focuses on evaluating the security of an application's configuration and deployment processes. This phase involves reviewing how the application and its supporting infrastructure are configured, including server settings, application parameters, and deployment practices. It aims to identify misconfigurations or insecure settings that could lead to vulnerabilities. Testing includes verifying proper use of secure protocols, reviewing default configurations, ensuring correct access controls, and assessing deployment scripts for security issues. By thoroughly examining these aspects, security professionals can ensure that the application is securely configured and deployed, minimizing the risk of exploitation due to misconfigurations or deployment flaws.
* _**Identity Management Testing:**_ Identity Management Testing, in the OWASP context, involves evaluating how an application handles user authentication, authorization, and identity management processes. This testing phase focuses on verifying the strength and effectiveness of mechanisms used for user identity verification and access control. It includes assessing password policies, multi-factor authentication implementations, session management practices, and user account provisioning and de-provisioning processes. Additionally, testers examine how the application handles user roles and permissions to ensure they are correctly enforced and do not expose users to unauthorized access. By scrutinizing these components, security professionals can identify and address weaknesses that might allow unauthorized access or compromise user data.
* _**Authentication Testing:**_ Authentication Testing in OWASP involves examining the mechanisms that verify user identities to ensure they are robust and secure. This process includes assessing the effectiveness of login systems, password policies, and multi-factor authentication methods. Testers evaluate how the application handles authentication credentials, such as passwords and tokens, to ensure they are stored securely and transmitted safely. Additionally, testing includes checking for vulnerabilities like weak password policies, improper session management, and susceptibility to brute-force attacks. By identifying weaknesses in authentication processes, security professionals can improve the system's resilience against unauthorized access and protect user accounts from compromise.
* _**Authorization Testing:**_ Authorization Testing in OWASP focuses on verifying that users have appropriate access rights and permissions within an application. This involves assessing whether users can access only the resources and functionalities they are authorized to use based on their roles or permissions. Testers examine access control mechanisms, such as role-based access control (RBAC) and attribute-based access control (ABAC), to ensure they are correctly implemented and enforced. The goal is to identify and address issues like privilege escalation, unauthorized access to restricted areas, and insufficient access controls. Effective authorization testing helps ensure that users cannot perform actions or access data beyond their intended scope, thus protecting sensitive information and maintaining proper access boundaries.
* _**Session Management Testing:**_ Session Management Testing in OWASP involves evaluating how an application handles user sessions to ensure secure and effective session management practices. This testing focuses on verifying that sessions are properly created, maintained, and terminated according to security policies. Key aspects include checking for secure session identifiers, ensuring proper session expiration and invalidation upon logout or inactivity, and examining the application's handling of session cookies and tokens. Testers also look for vulnerabilities such as session fixation, session hijacking, and improper session handling that could allow unauthorized users to gain access or impersonate legitimate users. Effective session management testing helps protect user sessions from being exploited, ensuring that session data remains secure, and that users' identities are correctly managed throughout their interactions with the application.
* _**Input Validation Testing:**_ Input Validation Testing in OWASP involves assessing how an application handles user inputs to ensure that it correctly validates and sanitizes data before processing. This testing aims to prevent common vulnerabilities such as SQL injection, cross-site scripting (XSS), and command injection, which can arise from improper handling of user inputs. Testers check that the application enforces strict input validation rules, including type checks, length constraints, and format validation. They also ensure that the application properly escapes or sanitizes inputs to prevent malicious data from being executed or processed. Effective input validation testing helps mitigate risks associated with untrusted data and ensures that the application can handle inputs securely and robustly.
* _**Testing for Error Handling:**_ Testing for Error Handling involves evaluating how an application manages and responds to unexpected conditions or errors. This type of testing ensures that the application does not expose sensitive information, such as stack traces, database errors, or system details, which could be exploited by attackers. During testing, evaluators intentionally cause errors to observe the application’s behavior, checking for proper error messages, logging, and user notifications. Effective error handling should include graceful degradation, where the application continues to function securely, and proper logging of error details for monitoring and debugging without revealing sensitive information to the user. Robust error handling is crucial for maintaining security and improving the application’s resilience against potential attacks.
* _**Testing for Weak Cryptography:**_ Testing for weak cryptography involves assessing the strength and effectiveness of an application's encryption and hashing mechanisms to ensure they meet current security standards. This process includes examining the cryptographic algorithms used for data protection, such as AES for encryption or SHA-256 for hashing and verifying that they are not vulnerable to known attacks. Evaluators look for the use of outdated or insecure algorithms, weak key management practices, and improper implementation of cryptographic protocols. Testing also involves checking for vulnerabilities like weak key lengths, predictable IVs (Initialization Vectors), and inadequate entropy sources. By identifying and addressing weak cryptographic practices, organizations can safeguard sensitive data from potential breaches and ensure robust data protection.
* _**Business Logic Testing:**_ Business logic testing involves evaluating an application to ensure its processes and workflows align with the intended business rules and objectives. This type of testing focuses on verifying that the application performs functions correctly according to the business requirements, without exposing vulnerabilities or allowing misuse. It includes examining how the application handles complex transactions, workflows, and interactions among different components. The goal is to identify flaws in logic that could lead to security issues, such as unauthorized access, data manipulation, or process bypassing. Effective business logic testing ensures that the application supports the organization's operational needs while maintaining security and integrity.
* _**Client-Side Testing:**_ Client-side testing involves evaluating the components of a web application that run on the user's device, such as browsers or mobile applications. This type of testing focuses on the security and functionality of client-side code, including JavaScript, HTML, CSS, and other scripts that execute in the user's environment. It aims to identify vulnerabilities such as cross-site scripting (XSS), insecure data storage, or improper handling of client-side validation. By ensuring that client-side code adheres to security best practices and properly interfaces with the server, client-side testing helps protect against attacks that target the user's interaction with the application and ensures a secure and seamless user experience.
* _**Server-Side Testing:**_ Server-side testing involves assessing the security and functionality of the components and code that run on the server, such as web servers, application servers, and databases. This testing focuses on identifying vulnerabilities within server-side code and configurations, including issues like improper input validation, insecure data storage, and misconfigured server settings. It evaluates how well the server handles requests, processes data, and interacts with the client side, ensuring that the server effectively implements security controls, enforces access permissions, and safeguards sensitive information. By identifying and addressing server-side vulnerabilities, this testing helps prevent potential attacks and ensures the robustness and integrity of the server infrastructure.

By offering practical guidance and a collaborative platform for security professionals, OWASP aims to raise awareness, improve security practices, and protect organizations from evolving cyber threats.
