# COMPUTER NETWORKING AND TCP

**COMPUTER NETWORKING AND TCP/IP CONCEPTS**

**After reading this chapter, you will be able to:**

* Explain the TCP/IP protocol stack
* Explain the basic concepts of IP addressing
* Compare the binary, octal, and hexadecimal numbering systems

Almost everything you do as an ethical hacker or network security analyst, or even security tester depends on your understanding of networking concepts and knowledge of the Transmission Control Protocol (TCP) and Internet Protocol (IP). It’s assumed you have some familiarization with networking concepts and TCP/IP or are CompTIA Network+ certified or have equivalent knowledge. This chapter, however, serves as a review of how these topics relate to IT security and security testers. In the activities and case project, you apply your knowledge of TCP/IP and networking concepts to security testing techniques.

Most of the tools both cyberattackers and security testers use run over IP, which is a standard networking protocol; however, IP version 4 (IPv4), still the most widely used version, was developed without security functions and features in mind, so professionals need the knowledge and skills necessary to tighten security holes resulting from the use of IP.

In this chapter, you examine the TCP/IP protocol stack and IP addressing. You will also review the binary, octal, and hexadecimal numbering systems and the ports associated with services that run over the TCP/IP stack.

For computers to communicate with one another over the Internet or across an office, they must speak the same language, like how we humans do. This language, however, in the context of computer networking is referred to as a _**protocol,**_ and the most widely used in computer networking worldwide is the _**Transmission Control Protocol/Internet Protocol (TCP/IP).**_ No matter what medium connects workstations on a network – be it copper wires, fiber optic cables, or a wireless network setup – the same protocol must be running on all connected devices if communication is going to function correctly.

You’ve probably had some kind of introduction to TCP/IP, but a review is helpful to ensure you have a thorough understanding of its innerworkings and how it functions on the world wide web and in our daily lives. TCP/IP is more than simply the combination of two protocols (TCP and IP). It’s usually referred to as the _**TCP/IP stack,**_ which contains four distinct layers:

1. **The Network Layer:** Concerned with physically moving bits across a medium (whether the medium is copper wire, fiber optic cables, coaxial cable, or wireless).
2. **The Internet Layer:** Responsible for routing packets by using Internet Protocol (IP) addresses.
3. **The Transport Layer:** Concerned with controlling the flow of data, sequencing packets for reassembly, and encapsulating segments with a TCP or _**User Datagram Protocol (UDP)**_ header.
4. **The Application Layer:** Layer where applications and protocols, such as HTTPS and SSH, operate.

This chapter discusses only the Application, Transport, and Internet layers, covered in the following sections, because security testing doesn’t usually involve getting down to the Network layer’s hardware level; however, some computer attacks use physical hardware, such as a _**keylogger.**_

The Transport layer is where data is encapsulated into segments. A segment can use TCP or UDP as its method for connecting to and forwarding data to a destination host (or node). TCP is a _**connection-oriented protocol,**_ meaning the sender doesn’t send any data to the destination node until the destination node acknowledges that it’s listening to the sender. In other words, a connection is established before data is sent. For example, if Computer A wants to send data to Computer B, it sends Computer B a SYN packet first. A _**SYN**_ (short for synchronize) packet is a query to the receiver, much like asking, _“Hello, Computer B, are you there?”_ Computer B then sends back an acknowledgement called a _**SYN/ACK**_ packet, which is like replying, _“Yes, I’m here. Go ahead and send.”_ Finally, Computer A sends an _**ACK**_ (short for acknowledgment) packet to Computer B in response to the SYN/ACK. This process, called the _**TCP Three-Way Handshake**_ involves the following steps:

1. Computer A sends a TCP packet with the SYN flag set (e.g., a SYN packet) to Computer B.
2. After receiving the packet, Computer B sends Computer A its own SYN packet with an ACK flag set (a SYN/ACK packet).
3. In response to the SYN/ACK packet from Computer B, Computer A sends Computer B a TCP packet with the ACK flag set (an ACK packet).

**TCP Flags**

Each _**TCP flag**_ occupies 1 bit of the TCP segment and can be set to either 0 (off) or 1 (on). These are the six flags of a TCP segment:

* **SYN flag:** The synchronize flag signifies the beginning of a session.
* **ACK flag:** The acknowledgement flag acknowledges a connection and is sent by a host after receiving a SYN/ACK packet.
* **PSH flag:** The push flag is used to deliver data directly to an application. Data isn’t buffered; it is sent immediately.
* **URG flag:** This flag is used to signify urgent data.
* **RST flag:** The reset flag resets or drops a connection.
* **FIN flag:** the finish flag signifies that the connection is finished.

**Initial Sequence Number (ISN)**

The _**Initial Sequence Number (ISN)**_ is a 32bit number that tracks packets received by a node and allows reassembling large packets that have been broken up into smaller packets. Steps 1 and 2 of the three-way handshake send an ISN. That is, the ISN from the sending node is sent with the SYN packet, and the ISN from the receiving node is sent back to the sending node with the SYN/ACK packet. An ISN can be a quite large number because 232 allows a range of numbers from zero to more than four billion.

**NOTE: A TCP header’s ISN might not seem important to network security professionals who aren’t familiar with penetration testing or hacking techniques. In fact, most people ignore many of these fundamental concepts; however, numerous network attacks have used&#x20;**_**network session hijacking,**_**&#x20;an attack that relies on guessing the ISNs of TCP packets. One of the most famous is Kevin Mitnick’s attack on a Japanese corporation – referred to as a&#x20;**_**“TCP sequence prediction attack.”**_**&#x20;Understanding TCP flags and the basic elements of a TCP packet can go a long way toward understanding how an adversary thinks – and how you should think. To become a better security professional and ethical hacker, try to discover vulnerabilities or weaknesses as you study the basics. Too many network security professionals and ethical hackers wait for adversaries to discover vulnerabilities in a network instead of beating them at their own game.**

**TCP Ports**

A TCP packet has two 16-bit fields containing the source and destination port numbers. A _**port**_ is the logical, not physical, component of a TCP connection and can be assigned to a process that requires network connectivity. For example, the HTTPS service uses port 443 by default. Understanding ports is important so that you know how to stop or disable services that aren’t being used on your network. The more services you have running on a server or device, the more ports are open for a potential attack, thereby increasing the digital attack surface. In other words, securing a house with 1000 open doorways is more difficult than securing a house with only 10 open doorways.

**NOTE: The most difficult part of a network security professional’s job is balancing system security with ease of use and availability for users. Closing all ports and stopping all services would certainly make your network more secure, but your users won’t be able to connect to the Internet, send or receive emails, or access any network resources. So, your job is to allow users to work in a secure network environment without preventing them from using valuable network resources such as email and web browsing. This task isn’t easy, as you’ll learn throughout this chapter. Remember, there is no such thing as absolute security, so finding the balance between protecting the network and its users while also including the allowance for access to critical network resources is something you’ll learn on your own the more you involve yourself in networking computing, protocols, and process components.**

A possible 65,535 TCP and UDP port numbers are available, but the good news is that only 1024 (actually 1023) are considered as _**ephemeral,**_ or _**well-known ports**_. To see a list of well-known ports, visit the **Internet Assigned Numbers Authority (IANA)** at [www.iana.org](http://www.iana.org/). The website provides more information than you probably need, but navigating the site gives you practice in searching for information. A successful security professional and ethical hacker knows how to be persistent in looking for answers by using a structured methodology.

**TIP: You can access the page about well-known ports by entering** [**www.iana.org/assignments/port-numbers**](http://www.iana.org/assignments/port-numbers) **as the URL, but you bypass the IANA homepage, which has more information and access to the IANA WHOIS service. You can review this service while browsing the IANA page.**

You don’t need to memorize the 1023 well-known ports; however, you should memorize the following TCP ports and the services they represent. Much of what you do as security professional and ethical hacker relies heavily on understanding the ins and outs of this information.

* **Ports 20 and 21 (File Transfer Protocol (FTP)):** FTP has been around as long as the Internet. It was the standard for moving and copying large files and is still in use today. I actually used it this morning before starting this chapter using **FileZilla,** a free FTP solution for both clients and servers, and is an open-source software distributed free of charge to use _(Source:_ [_https://filezilla-project.org_](https://filezilla-project.org/)_)._ Although FTP is still used today, much of it is utilized to a lesser extent because of the popularity of HTTP. FTP uses port 20 for data transfer and port 21 for control. FTP requires entering a logon name and password and is inherently more secure than the _**Trivial File Transfer Protocol (TFTP),**_ covered later in this list. FTP does not use encryption, so data in transit can be intercepted and understood. _**Secure File Transfer Protocol (SFTP)**_ uses _**Secure Shell (SSH)**_ to make FTP secure by providing encryption and authentication.
* **Port 22 (Secure Shell (SSH)):** Secure Shell (SSH) uses encryption and authentication to create a secure channel over an unsecure network. SSH is used to secure logons, file transfers, and port forwarding. FTP is unsecure, but you can make it secure by using an SSH channel. FTP using SSH is known as SFTP.
* **Port 25 (Simple Mail Transfer Protocol (SMTP)):** Email servers listen on this port. If you attempt to send email to a remote user, your workstation connects to port 25 on a mail server.
* **Port 53 (Domain Name System (DNS)):** If a server on your network uses DNS, it is using port 53 (TCP or UDP). Most networks require a DNS server so that users and devices can connect to websites or networks with URLs vice IP addresses. When a user enters a URL, such as [www.google.com](http://www.google.com/), the DNS server resolves the name to an IP address (e.g., [www.googlecom](http://www.googlecom/) -> 8.8.8.8). The DNS server might be internal to a company, or each computer might be configured to pint to the IP address of an external DNS server that’s hosted by the company’s ISP.
* **Port 69 (Trivial File Transfer Protocol (TFTP)):** Many network engineers use the TFTP service to transfer router and switch backup configurations from a laptop to install on another router or switch. It’s a protocol that provides the receiving and transferring of backup configuration from one network device to another by using manual methods using a laptop connected to the router or switch via console cable to retrieve and backup/install configurations.
* **Port 80 (Hypertext Transfer Protocol (HTTP)):** Port 80 is used when you connect to a web server via web browser. HTTP is not secure, so most web servers in use today use HTTPS (port 443).
* **Port 143 (Internet Message Access Protocol (IMAP)):** IMAP is an internet protocol that allows clients to access email messages from a mail server over a TCP/IP connection. IMAP acts as an intermediary between email servers and clients, allowing users to access their emails from any device at any time. With IMAP, messages are stored on an external mail server and only downloaded when clicked on, so users can read messages from the email service without downloading them or storing them on a computer. IMAP also syncs changes across multiple devices, so users can be logged in with multiple computers and devices simultaneously.

* **Port 443 (Secure Hypertext Transfer Protocol (HTTPS)):** The Hypertext Transfer Protocol Secure (HTTPS) is an extension of the Hypertext Transfer Protocol (HTTP) that uses encryption to secure communications over a computer network. HTTPS is a combination of HTTP and Transport Layer Security (TLS), a network protocol that creates an encrypted connection to an authenticated node over an untrusted network.
* **Port 993 (Internet Message Authentication Protocol Secure (IMAPS)):** IMAPS (IMAP over SSL) means that IMAP traffic travels over a secure socket to a secure destination port, typically TCP port 993. Connections using this port are secured, so it is preferred over the unsecured version of IMAP, which uses port 143.

**TIP: Often technical personnel who aren’t familiar with security techniques think that restricting access to ports on a router or firewall can protect a network from attacks. This is way easier said than done. Afterall, if a firewall prevents any traffic from entering or exiting a network on ports 80 and 443, you have indeed closed vulnerable ports to access from malicious actors; however, you have also closed the door to Internet access for your uses (unless you segment groups into their own rulebases or access control lists (ACLs), and this action is probably not acceptable in any organization requiring online services. The tricky (and most impossible) part of security personnel is attempting to keep out malicious actors while allowing authorized users to work proficiently and use the internet. As you progress through this book, you’ll see that as long as users can connect to the Internet through an open port, attackers can get in. It’s that simple. If a user can get out, an attacker can get in.**

* **Port 110 (Post Office Protocol (POP3)):** To retrieve email from a mail server, one option is to access port 110 using the Post Office Protocol version 3 (POP3). An enhanced email retrieving protocol, IMAP4, is also available and is covered later in this list. POP3 is still around; however, is one of the most common email retrieval systems.
* **Port 119 (Network News Transfer Protocol (NNTP)):** NNTP (Network News Transfer Protocol) is the predominant protocol used by computers, servers, and clients for managing and maintaining poses on Usenet newsgroups. NNTP replaced the original Usenet protocol, UNIX-to-UNIX Copy Protocol (UUCP), some time ago. NNTP server manages the global network of collected Usenet newsgroups.
* **Port 135 (Remote Procedure Call (RPC)):** Remote Procedure Call (RPC) is a protocol that provides the high-level communications paradigm used in a Windows operating system for the operation of Microsoft Exchange Server (email) and Active Directory (AD). RPC presumes the existence of a low-level transport protocol, such as TCP/IP or UDP, for carrying message data between communicating programs. RPC implements a logical client-to-server communications system designed specifically for the support of network applications. The RPC protocol is built on top of the _**eXternal Data Representation (XDR)**_ protocol, which standardizes the representation of data in remote communications. XDR convers the parameters and results of each RPC service provided. The RPC protocol enables users to work with remote procedures as if the procedures were local to them. The remote procedure calls are defined through routines contained in the RPC protocol. Each call message is matched with a reply message. The RPC protocol is a message-passing protocol that implements other non-RPC protocols such as batching and broadcasting remote calls. The RPC protocol also supports callback procedures and the **select** subroutine on the server side.
* **Port 139 (Network Basic Input/Output System (NetBIOS)):** A network service that allows applications on different computers to communicate over a local area network (LAN). It was originally developed by IBM in the 1980s for use on early PC networks and was later adopted by Microsoft for use in Windows operating systems. NetBIOSs main purpose is used by the Microsoft NetBIOS session service to allow applications to establish sessions and access shared resources, such as files and printers.
* **Port 143 (Internet Message Access Protocol 4 (IMAP4)):** Internet Message Access Protocol, Version 4 (IMAP4), is an _**Application Programming Interface (API)**_ that allows a user’s email program to access their mail server and manage email messages remotely. IMAP4 was developed at the University of Washington to address some of the limitations of POP3, another popular standard as described above, for retrieving mail.

**User Datagram Protocol (UDP)**

User Datagram Protocol (UDP) represents an alternative approach to data transmission son the Internet, prioritizing speed over reliability. It functions at the Transport layer, offering a quick by potentially unreliable means of delivering information. To draw an analogy, imagine launching a mail delivery service where speed is emphasized over accuracy – akin to tossing letters out of a moving vehicle without ensuring they reach the intended recipient. Despite its lack of reliability, UDP has found widespread adoption due to its efficiency. It operates under the assumption that the recipient is prepared to receive data packets, without taking the steps to confirm readiness. Essentially, UDP sends data regardless of whether the receiver is ready, contributing to its faster transmission rates compared to protocols that ensure delivery confirmation as does TCP.

Some applications utilizing incorporate mechanisms to alert senders about undelivered messages, but UDP itself lacks this functionality. Instead, it relies on higher layers within the TCP/IP (or protocol suite) to address issues related to message delivery and error handling. To illustrate, imagine a school announcement made over a loudspeaker about an afternoon closure – some student might catch the news, while others miss out entirely. This scenario mirrors UDPs connectionless nature, contrasting sharply with the connection-oriented approach of the Transmission Control Protocol (TCP). TCP ensures reliable data transfer through features like guaranteed packet delivery, error checking, packet reconstruction, fragmentation, and flow control, among others.

The Internet Control Message Protocol (ICMP) serves as a communication tool for conveying information about network operations. A prime example of its utility is when a packet fails to arrive at its intended destination, resulting in a “Destination Unreachable” error message. ICMP facilitates network troubleshooting by enabling you to diagnose connectivity issues using commands like ping, which checks network reachability, and traceroute, which maps the path packet stake from a source IP to a destination IP. Additionally, security professionals leverage ICMP type codes to manage network traffic, such as configuring routers to prevent certain ICMP packets, like those with type code 8 (Echo Request), from entering or exiting a network. To illustrate, attempting to ping www.microsoft.com typically yields no response because Microsoft restricts pinging of its IP address(es), effectively blocking ICMP Echo Requests.
