# 4.1 Implement Centralized Servers

To ensure a robust AAA (Authentication, Authorization, and Accounting) system, all devices should be configured to utilize centralized AAA servers. It is recommended to have at least two AAA servers in place to guarantee availability and aid in detecting and preventing adversary activities. In case one server is unavailable due to maintenance or other reasons, the remaining servers can continue providing centralized AAA services. The configuration of these servers should include the following aspects:

1. <mark style="color:yellow;">**Authentication with Unique Pre-Shared Key**</mark>: Configure servers to authenticate devices using a unique and complex pre-shared key. This step ensures that only authorized devices can access AAA services. For guidance on creating strong passwords, refer to section 5.5.
2. <mark style="color:yellow;">**Consistent Protocol Usage**</mark>: Use the same protocol (e.g., TACACS+, RADIUS, or LDAP) across all servers for consistency. Additionally, utilize encrypted transport protocols like RadSec, Diameter, LDAPS, or IPsec encapsulated when supported to enhance security.
3. <mark style="color:yellow;">**Synchronization**</mark>: Ensure that all AAA servers are synchronized with each other to maintain consistency in user credentials and access controls.

Here is an example configuration for setting up a server group with multiple AAA servers:

```bash
aaa group server {tacacs+ | radius | ldap} <GROUP_NAME>
server-private <IP_ADDRESS_1> key <KEY_1>
server-private <IP_ADDRESS_2> key <KEY_2>
```

For older devices using keywords like `tacacs-server` and `radius-server`, it's essential to replace them with the above configuration format to assign a unique pre-shared key to each server. This practice ensures that if an adversary gains access to the pre-shared key of one server, only that server needs revocation, while others with different keys can still be used securely.
