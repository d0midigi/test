# 3.1 Verify Software and Configuration Integrity

To ensure the integrity of software and configurations on network devices, it is essential to verify that they have not been maliciously altered by adversaries. Adversaries can compromise network devices by modifying operating system files, executable code in memory, firmware, or bootloaders, potentially leading to data integrity violations, sensitive information theft, or denial of service (DoS) attacks.

One recommended practice, as per industry standards, is to verify the integrity of operating system files by comparing their cryptographic hash with the known good hash provided by the vendor. This verification process helps detect any unauthorized modifications. For example, you can compute a SHA-512 hash for an operating system image file using the command:

```plaintext
verify /sha512 <PATH:filename>
```

For older devices that support only MD5 hashing, you can use the following command:

```plaintext
verify /md5 <PATH:filename>
```

After computing the hash, compare it with the information published by the vendor on their support pages to ensure its integrity.

Additionally, it's crucial to implement a configuration change control process to monitor and detect unauthorized modifications to device configurations. This process involves securely creating backups of device configurations, documenting authorized configuration changes with proper authorization, purpose, and mission justification, and periodically comparing current configurations with the most recent backups to identify any suspicious changes.

By following these practices, organizations can enhance their network security by ensuring the integrity of both software and configurations on network devices, thereby reducing the risk of unauthorized access and potential compromises.
