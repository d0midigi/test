# 2.6 Limit Virtual Private Networks (VPNs)

***

Establishing a VPN tunnel between two endpoints is crucial for creating an encrypted communication channel across a network. This method should be employed when ensuring the confidentiality and integrity of traffic through other means is not feasible. However, VPN gateways are often accessible from the Internet and susceptible to network scanning, brute force attacks, and zero-day vulnerabilities. To address these risks, it's essential to disable unnecessary features on VPN gateways and enforce strict traffic filtering rules.

```plaintext
Disable default policies and proposals for ISAKMP and IKEv2:
no crypto isakmp default policy
no crypto ikev2 policy default
no crypto ikev2 proposal default
no crypto ipsec transform-set default
```

```plaintext
crypto isakmp policy <POLICY_NUMBER>
encryption aes 256
hash sha-384
group 16
lifetime 86400
```

The above commands configure an ISAKMP (Internet Security Association and Key Management Protocol) policy with strong encryption, hashing, and key exchange settings to establish secure communication.

For IPsec (Internet Protocol Security) VPN configurations, the following parameters are recommended based on CNSSP 15 guidelines:

```plaintext
crypto ipsec transform-set <TRANSFORM_SET_NAME> esp-aes 256 esp-sha-384-hmac
mode tunnel
```

These commands define an IPsec transform set with AES-256 encryption and SHA-384 hashing for tunnel mode communication.

Additionally, to ensure that weak cryptographic algorithms are not used and to disable default policies and proposals, execute the following commands:

```plaintext
no crypto isakmp default policy
no crypto ikev2 policy default
no crypto ikev2 proposal default
no crypto ipsec transform-set default
```

These commands disable default policies and proposals for ISAKMP and IKEv2, ensuring that only explicitly configured policies are utilized.

To enhance security further, it's recommended to limit access to VPN gateways to specific ports and protocols, such as UDP ports 500 and 4500, and Encapsulating Security Payload (ESP). Additionally, restricting traffic to known VPN peer IP addresses adds an extra layer of protection. In cases where IP filtering isn't feasible, an Intrusion Prevention System (IPS) can be deployed to monitor IPsec traffic for anomalies and potential security threats.

For IPsec VPN configurations, it's imperative to define strong policies for Internet Key Exchange (IKE) and IPsec negotiations. Weak cryptography settings in either phase can compromise the entire VPN and lead to data confidentiality breaches. Here are the minimum recommended settings based on CNSSP 15 guidelines:

* Diffie-Hellman Group: 16 with 4096-bit MODP
* Diffie-Hellman Group: 20 with 384-bit elliptic curve group (ECP)
* Encryption: Advanced Encryption Standard (AES)-256
* Hash: Secure Hash Algorithm (SHA)-384

While Diffie-Hellman Group 15 meets minimum requirements, it's not advisable due to observed interoperability issues.

When configuring VPN proposals, policies, or transform-sets, ensure compliance with CNSSP 15 recommendations. The details of CNSSP 15 requirements can be found in the IETF document on "Commercial National Security Algorithm (CNSA) Suite Cryptography for IPsec."

***

When disabling default policies, it's important to note that only explicitly configured policies will be utilized. To establish an IKEv2 (Internet Key Exchange version 2) proposal, policy, and profile, the following configuration commands can be used:

```plaintext
crypto ikev2 proposal <IKEV2_PROPOSAL_NAME>
encryption aes-gcm-256
group 16
```

The above commands define an IKEv2 proposal with AES-GCM-256 encryption and Group 16 key exchange.

Next, configure an IKEv2 policy that references the previously defined proposal:

```plaintext
crypto ikev2 policy <IKEV2_POLICY_NAME>
proposal <IKEV2_PROPOSAL_NAME>
```

This policy is associated with the IKEv2 proposal created earlier.

Now, create an IKEv2 profile that includes authentication methods, identity matching, and a keyring for pre-shared keys:

```plaintext
crypto ikev2 profile <IKEV2_PROFILE_NAME>
match identity remote ...
authentication remote ...
authentication local ...
keyring <KEYRING_NAME>
```

The profile configuration depends on the specific network requirements and must include appropriate authentication methods.

After setting up the IKEv2 components, establish an IPsec transform-set for secure communication:

```plaintext
crypto ipsec transform-set <IPSEC_TRANSFORM_NAME> esp-gcm 256
mode tunnel
```

This transform-set uses AES-GCM-256 encryption for tunnel mode IPsec communication.

Next, create an IPsec profile that references the IKEv2 profile and IPsec transform-set:

```plaintext
crypto ipsec profile <IPSEC_PROFILE_NAME>
set transform-set <IPSEC_TRANSFORM_NAME>
set pfs group16
set ikev2-profile <IKEV2_PROFILE_NAME>
```

The IPsec profile specifies the transform-set, perfect forward secrecy (PFS) group, and the IKEv2 profile to be used.

Finally, apply the IPsec profile to the tunnel interface and ensure it is active:

```plaintext
interface <TUNNEL_INTERFACE_NAME>
tunnel protection ipsec profile <IPSEC_PROFILE_NAME>
no shutdown
```

These commands configure the tunnel interface to use the specified IPsec profile for protection and activate the tunnel interface for secure communication.

By following these configuration steps, you can establish a secure VPN tunnel with strong encryption, authentication, and key management protocols.
